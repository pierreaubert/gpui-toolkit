# Review: Vello adoption status in d3rs / px / ui-kit + vello text assessment

Date: 2026-08-22
Scope: `gpui-d3rs`, `gpui-px`, `gpui-ui-kit` code review against the 2026-08-21
plan (`reviews/20260821-vello.md`), plus an evaluation of replacing the current
text stack with vello's text rendering.

## Verdict (TL;DR)

- The Vello default is real for the core chart marks: all 10 ordinary px chart
  builders expose `renderer_2d`/`vello_backend` and default to
  `Renderer2D::Vello` + `VelloBackend::Auto` under default features.
- The plan's *library-owned dispatch* invariant is **not met**: selection is
  caller-side (`render_*_vello` free functions), geometry is rebuilt per
  producer closure, and one config knob (`ContourConfig.renderer_2d`) is dead.
- `gpui-ui-kit` needs **no** Vello work — but it contains an orphaned,
  uncompilable `src/audio/` tree that should be deleted, and dead `gpu-2d`/
  `gpu-3d` features in its `Cargo.toml`.
- Vello text: **do not replace GPUI's text system**. It is worth considering
  only for the self-contained d3rs chart-label paths (fontdue/SVG and the gpu2d
  atlas), and even there it is a medium-effort, low-urgency consolidation.

## 1. gpui-d3rs

### 1.1 Architecture as found

- Feature gating (`crates/gpui-d3rs/Cargo.toml:17,27-28`): `vello` (IR +
  `vello_cpu` rasterizer), `vello-gpui` = `vello` + `gpui` + `gpu-2d`. Note:
  `vello-gpui` force-compiles the legacy `gpu2d` shader stack; the "escape
  hatch" is never actually compiled out in GPUI builds.
- `render2d.rs:5-22`: `Renderer2D::{Vello, Legacy}`, default Vello under
  `vello-gpui`; `VelloBackend::{Auto, Wgpu, Cpu}`, default `Auto` (:49-58).
- `vello2d/scene.rs`: `ChartScene` IR = `ChartCmd::{Fill, Stroke}` only
  (:11-24). Helpers: `fill_path/circle/rect/rounded_rect/wedge`,
  `stroke_arc/path/polyline`. Monotonic `revision` for retained painters.
- `vello2d/element.rs`: `VelloScenePainter` (retained, used by audio-kit) and
  `VelloChartElement`. `Auto` probes `wgpu_custom_draw_available()`, falls
  back to CPU with unregister on GPU init failure (:145, :393). CPU path does
  RGBA→BGRA swap for the GPUI atlas (:557-565).
- `vello2d/wgpu_draw.rs`: zero-copy `WgpuCustomDraw` — vello renders into an
  offscreen `Rgba8Unorm` storage texture, then a bespoke WGSL pipeline
  alpha-composites into the GPUI frame with a source sub-rect clip (:70,
  :241-280).

### 1.2 Mark producer inventory

| scatter | `shape/scatter.rs:396` | `render_scatter_vello` (:532); exported `scatter_chart_scene` (:512) | caller-side |

### 1.3 Findings — gaps and defects

**Structural**

1. **No in-library dispatch.** `LineConfig`/`BarConfig`/`ScatterConfig` carry
   no renderer field; every caller picks `render_x` vs `render_x_vello` itself.
   This contradicts plan workstream 2 ("one selection/dispatch helper per mark
   family") and is the root cause of the remaining bypasses below.
2. **`ContourConfig.renderer_2d`/`vello_backend` are dead** — written at
   `contour_config.rs:58`, never read; `ContourElement` ignores them. Either
   wire them up or remove the fields; as-is they are a false promise.
3. **Geometry duplication between renderers.** Vello scene construction is
   inline per producer closure and diverges from the Legacy normalization —
   e.g. `contour/render.rs:104-159` re-implements `contour_element.rs:93-247`
   but **drops Chaikin smoothing and jump splitting**. That is a visible
   rendering difference between Vello and Legacy contours, not just a code
   smell.

**Remaining non-Vello consumers that should migrate or be labeled**

4. **spinorama demo** still renders contours/heatmap/bands through the gpu2d
   shader stack (`bin/spinorama_demo/app/mod.rs:24-26`).
5. **Showcase D3 examples bypass the renderer contract entirely** — pie, donut,
   chord, force_directed, radial_tree, star_map, horizon, voronoi paint via
   `canvas`+`paint_path` through `d3rs_path_to_gpui_simple` (e.g.
   `pie_chart.rs:101-108`, `chord.rs:182-189`). Plan workstream 4 said "normal
   D3 examples" go through dispatch helpers; they don't. Several of these
   (pie/donut/arcs) are exactly Vello-shaped content.
6. **gpu2d axis/grid + fontdue text atlas** (`gpu2d/shapes/render.rs:334,435`,
   `gpu2d/text/`) are only consumed by spinorama/examples — dead weight once
   gpu2d shrinks to an escape hatch.

**vello2d implementation gaps (vs plan "scene primitive completeness")**

7. **No clip or layer-opacity commands in the IR** — `ChartCmd` is only
   Fill/Stroke. Opacity is folded into brush alpha at every producer; clipping
   is delegated to GPUI element bounds. The plan explicitly required both.
8. **Fill rule hardwired to `NonZero`** (`scene.rs:51-58`); the `fill` field
   exists but nothing sets `EvenOdd`.
9. **No annular (inner-radius) wedge** — donut/ring producers can't use
   `fill_wedge`. Consequently px pie, boxplot, treemap hand-roll `BezPath`
   geometry instead of using scene helpers; `fill_wedge`/`stroke_arc`/
   `fill_rounded_rect` are exercised only by tests and gpui-audio-kit.
10. **Arcs/wedges are polyline approximations** (π/8 segments, clamped 256 —
    `scene.rs:182-183`) instead of kurbo `Arc`/cubics. Acceptable at chart
    scale; document it.
11. **CPU backend silently drops image brushes** (`cpu.rs:67-68`, log-only).
12. **`render_*_vello` are gated `#[cfg(all(feature = "vello-gpui", not(test)))]`**
    (`shape/mod.rs:70-87`, `contour/render.rs:78`) — scene construction is
    trapped inside closures and can't be unit-tested. Only
    `scatter_chart_scene` is exported under plain `vello`. This blocks the
    plan's deterministic CPU fixtures for line/bar/contour/heatmap. **Highest
    priority fix**: extract scene builders for every mark, exported like
    `scatter_chart_scene`.
13. **No sharing of GPU state across elements** — each `VelloChartElement`
    lazily creates its own `vello::Renderer`, offscreen texture, and composite
    pipeline (`wgpu_draw.rs:143-191`). A dashboard of 20 charts builds 20
    vello renderers. Consider per-device shared renderer/pipeline.
14. Dead commented-out enum block in `element.rs:18-25`.

## 2. gpui-px

### 2.1 Status: migration complete for ordinary marks

All 10 ordinary builders carry `renderer_2d` + `vello_backend` (scatter calls
it `raster_backend`, setter also forces `Renderer2D::Vello` —
`scatter_chart.rs:426-436`) and default to Vello:
line (`line_chart.rs:212-213`), area (`area.rs:30-31`), scatter
(`scatter_chart.rs:192-194`), bar (`bar_chart.rs:35-36`), boxplot
(`box_plot_chart.rs:32-33`), pie/donut (`pie.rs:33-34`), treemap
(`treemap.rs:71-72`), heatmap (`heatmap_chart.rs:35-36`), contour
(`contour_chart.rs:39-40`), isoline (`isoline_chart.rs:53-54`).

### 2.2 Findings

1. **Isoline's Legacy branch is the wgpu `gpu2d` module**
   (`isoline_chart.rs:12-18`), the only ordinary chart where "Legacy" means
   legacy-wgpu rather than GPUI canvas. On wasm this hits the deferred-readback
   caveat. Prefer the GPUI `ContourElement` as Legacy; keep gpu2d as a pure
   escape hatch.
2. **MeshPlot 2D modes still use `gpu2d::Chart2DElement` / custom wgpu**
   (`mesh_plot_chart.rs:1314-1335`) — explicitly out of plan scope, but it
   remains the largest gpu2d consumer in px.
3. **Axes, grids, legends never switch renderer** — always GPUI elements
   (e.g. `line_chart.rs:1027-1100`). Domain lines/ticks/grid lines are
   trivially scene-able, but per the plan text/axes are out of scope; fine to
   leave, worth noting as future consolidation.
4. **`Colorbar` has no renderer choice** — div gradients + glyph text
   (`colorbar.rs:114-135`). Low value; leave.
5. **Showcase renderer selector is misleading**: `?renderer=auto|cpu|legacy`
    only affects the Scatter and ScatterVello sections
    (`bin/showcase/showcase_app.rs:417-421,529-530`), yet the visual manifest
    claims `renderer_qa_queries: ["auto","cpu","legacy"]` for *every* section
    (`chart_section.rs:104`). Either thread the override through all sections
    or scope the manifest claim — the plan allowed either, but pick one.
6. Legacy fallbacks are uniformly GPUI `canvas`+`paint_path`; no other custom
   painting exists in px outside mesh_plot.

## 3. gpui-ui-kit

**No Vello work is warranted here.** No `vello`/`Renderer2D` reference exists
in the crate; its compiled custom painting is exactly the content GPUI-native
rendering is good at:

- spinner/progress rings — two stroked arcs via `canvas`+`paint_path`
  (`spinner.rs:146-157`, `progress.rs:285-295`): fine as-is;
- QR codes — axis-aligned `paint_quad` rects (`qr/paint.rs`): quads are the
  right primitive;
- workflow canvas connections — de-Casteljau-flattened stroked beziers
  (`workflow/canvas/draw.rs:47,115`): borderline; only revisit if profiling
  shows many-connection canvases as a hotspot;
- accordion/pane-divider rotated labels — `paint_svg`; inputs — GPUI
  `ElementInputHandler`. No custom rasterization anywhere compiled.

Two cleanups instead:

1. **Delete the orphaned `src/audio/` tree** (`potentiometer.rs`,
   `vertical_slider.rs`, `volume_knob.rs` — ~2600 lines). `pub mod audio;` was
   removed from `lib.rs` in `4d5c78c` when audio moved to `gpui-audio-kit`;
   the files don't compile, and their tests/examples are unregistered. The
   functionality already exists in Vello form in gpui-audio-kit. Keeping them
   invites someone to "fix" the wrong copy.
2. **Remove dead `gpu-2d`/`gpu-3d` features** from `Cargo.toml:52-53` — they
   gate nothing.

## 4. Should we adopt vello text?

### 4.1 What vello offers (0.10, current dep)

Vello itself ships only a **low-level glyph-drawing API**
([`Scene::draw_glyphs` / `DrawGlyphs`](https://docs.rs/vello/latest/vello/struct.DrawGlyphs.html)):
positioned glyph runs, per-glyph transforms, bitmap/COLR emoji support.
Shaping, line breaking, font discovery and fallback are **not** in vello — the
intended stack is **parley** (layout, on top of swash + fontique). Known
limitations vs native stacks: no subpixel AA, weaker hinting than
CoreText/DirectWrite, and shaping quality depends on the parley/swash version
pinned (see [linebender/vello#452](https://github.com/linebender/vello/issues/452)).

### 4.2 What we use today

Three-and-a-half independent text stacks coexist:

1. **GPUI `PlatformTextSystem`** (all UI text, legends, inputs):
   CoreText (macOS/iOS/AUv3), DirectWrite (Windows), **cosmic-text 0.17 +
   swash** (Linux/Android/wasm via `gpui_wgpu/src/cosmic_text_system.rs`).
   Glyph bitmaps → renderer atlas → textured quads. This is vendored Zed code
   (`crates/3rdparties/gpui`, tag v1.9.0) behind one trait.
2. **d3rs `text/glyph_text/`** (all chart axis/tick/title labels, via
   `d3rs::axis::render_axis` and every px chart): fontdue + embedded
   DejaVuSansMono metrics for measurement, then a **generated SVG string
   painted through `window.paint_svg`** — i.e. resvg/usvg with its own fontdb,
   a *third* font path. Rotation is software bitmap rotation
   (`rasterize.rs:15-27`).
3. **gpu2d text atlas** (`gpu2d/text/`, fontdue → wgpu textured quads): only
   used by `gpu2d::render_axis`, i.e. spinorama/examples and px-isoline-legacy.
4. **`gpui-pretext`**: measurement/line-breaking only (greedy + Knuth-Plass),
   no shaping/rendering; used by gpui-builder and the Python IR showcase.

### 4.3 Assessment

**Replacing GPUI's text system: no.**

- It would mean implementing a new `PlatformTextSystem` behind the trait —
  realistically only for the cosmic-text platforms (Linux/Android/wasm);
  CoreText/DirectWrite would remain. So the fragmentation stays, plus a new
  backend to maintain inside a vendored fork we deliberately keep close to
  upstream Zed. Every upstream sync gets harder.
- Quality regression on Linux/wasm is unlikely (parley/swash vs cosmic-text/
  swash is near a lateral move), but there is no quality *win* either, and
  subpixel AA / hinting parity with CoreText is not achievable.
- The only strategic argument — "one text stack everywhere, including charts"
  — doesn't survive contact with macOS/Windows remaining native.

**Replacing the d3rs chart-label paths: plausible, medium priority.**

The `glyph_text` + gpu2d-atlas paths are the real anomaly: self-contained,
already bypassing GPUI, with three font pipelines (fontdue metrics, resvg
fontdb, gpu2d atlas) for the same visual output, no system fonts, mono-only
metrics, software bitmap rotation, and SVG-string round-tripping for every
label. Options:

- **(a) Route chart labels through GPUI's native text** (styled elements /
  `ShapedLine` painting). Cheapest, deletes the fontdue+SVG path, gets system
  fonts, fallback, proper rotation for free. Legends already do this. Downside:
  labels become GPUI elements, so they can't be baked into a Vello scene or
  the static-SVG export (export already writes raw `<text>`, unaffected).
- **(b) Add glyph runs to the `ChartScene` IR and render labels with vello
  text (parley or direct `draw_glyphs` + swash metrics).** Labels bake into
  the same scene as the marks — one rasterizer, correct z-order/clipping,
  works identically on CPU and WGPU backends, and gives the gpu2d atlas a
  replacement. Cost: new font loading/shaping dependency (parley+fontique,
  ~swash is already in the tree via cosmic-text), plus solving font discovery
  on wasm (currently 8 bundled TTFs). Also note vello_cpu's text parity should
  be verified before committing fixtures to it.
- Recommendation: **(a) first** — it removes the worst stack (SVG-string
  labels) for almost no code; revisit (b) only if profiling shows label
  element overhead, or if scene-baked labels become necessary for export/QA
  determinism. Do not do (b) before fixing the scene-IR gaps in §1.3
  (clip/opacity) since labels will immediately want both.

## 5. Recommended actions, in order

1. Extract exported scene builders for all marks (à la `scatter_chart_scene`),
   un-`not(test)` them → unlocks the CPU fixture suite (§1.3.12).
2. Fix contour Vello/Legacy geometry divergence (Chaikin smoothing + jump
   splitting) (§1.3.3); then dedupe shared geometry per mark family per plan
   invariant 4.
3. Resolve or remove dead `ContourConfig.renderer_2d` (§1.3.2); decide whether
   library-owned dispatch goes into configs (preferred) or stays caller-side
   (document it).
4. Migrate px-isoline Legacy off `d3rs::gpu2d` onto the GPUI `ContourElement`;
   label spinorama as Legacy or migrate it (§1.3.4-5, §2.2.1).
5. Fix the px showcase manifest/renderer-selector mismatch (§2.2.5).
6. Add clip + layer-opacity commands to `ChartScene` IR; add annular wedge;
   use `fill_wedge` in px pie/donut (§1.3.7-9).
7. Share `vello::Renderer`/pipeline per device across `VelloChartElement`s
   (§1.3.13).
8. Delete ui-kit `src/audio/` orphans + dead `gpu-2d`/`gpu-3d` features (§3).
9. Text: route d3rs `glyph_text` chart labels through GPUI native text; retire
   the fontdue→SVG path and (with isoline/spinorama migrated) the gpu2d text
   atlas. Defer vello text; revisit only with concrete evidence (§4.3).
