# Bug Review: gpui-builder — 2026-08-25


## Completion audit — 2026-08-26

- [x] Text-measure cache identity/bounds, protected chassis sections, invalid fractional bounds and ratio input, divider-aware collapse and diagnostics, and the layout-showcase accessibility/drag/theme regressions are fixed as recorded above.
- [x] The `solve_layout!` macro now owns its declaration storage for the duration of solving rather than leaking it; the owned-result regression confirms declarations may drop after the macro expression returns.
- [x] The inspector's event-driven snapshot allocation and its separate diagnostic traversals are intentional diagnostic-only trade-offs, not solver hot-path leaks or a behavioral defect. Both divider-aware representations have regression coverage.

Verified `cargo test -p gpui-builder --features showcase` (134 passed).
Scope: full scan of the `gpui-builder` crate — the platform-agnostic solver core (`src/solver/*`, `src/types/*`, `src/solved/*`), state/preferences (`state.rs`), validation (`src/validation/*`), diagnostics/inspection (`src/inspector/*`, `src/solved/layout_debug_*`), snapshots/stories/visual-regression manifests, the plugin compat + chassis layers (`compat.rs`, `src/plugin_chassis/*`), the `solve_layout!` macro DSL, the `layout-showcase` GPUI binary (`src/bin/layout_showcase*`, behind the `showcase` feature), plus `Cargo.toml`, benches, examples, and integration tests (`tests/proptests.rs`, `tests/allocation_contracts.rs`). Roughly 40 source files / ~13k lines. The crate has no wgpu/GPU code and no threads of its own (only thread-locals), so those sections are limited accordingly.

## Findings

Ranked by severity.

## Resolved during follow-up (2026-08-26)

- **Text measurement cache identity and bounds:** `TextMeasure` now distinguishes an address-only default key from an explicit stable semantic key. Every solve gets a new epoch for address-only keys, preventing ABA reuse while preserving cache reuse for opt-in semantic keys. The retained maps are bounded (64 measure keys, 128 texts per key, and 128 size keys), and the default cache retains allocation capacity so warmed `solve_tree_into` remains allocation-free.
- **Protected chassis sections:** priority-1.0 sections are excluded from the collapse candidate set before selection, so narrow layouts clip protected sections without accidentally dropping one first.
- **Invalid fractional data and ratio overrides:** solver allocation normalizes fractional bounds without `f32::clamp` panics; preferences and state reject non-finite ratios and clamp finite ratios to `0.0..=1.0`.
- **Divider-aware collapse:** each collapsed visible child now releases one divider before the next collapse decision, preventing an additional panel from being hidden when the first collapse made enough room.
- **Duplicate solved ids:** the flat-tree index now keeps the first pre-order node, matching recursive `SolvedNode::find`; public docs state the deterministic fallback for invalid duplicate ids.
- **Divider-aware diagnostics:** solved recursive and flat nodes now retain their container divider size, and both debug-report paths include the dividers between visible children in main-axis overflow warnings.
- **`solve_layout!` declaration leak:** the macro now builds temporary boxed child arrays and returns `OwnedSolvedNode`, so the declaration storage drops immediately after solving instead of being leaked as `'static`. A regression verifies that locally borrowed declaration metadata is safely copied into the result.
- **Showcase collapsed-divider and drag scale:** sidebar dividers are now rendered only when their panel is visible, and drag gestures use the solver's distributable axis (content extent minus active dividers), so pointer motion maps directly to the stored fractional ratio.
- **Showcase theme and accessibility:** the showcase selects a light or dark palette from GPUI's live window appearance. Dividers are now focusable slider controls with a name, range/value metadata, visible focus styling, and arrow-key adjustment; visual-tree rows are focusable, labelled buttons selectable with Enter or Space.
- **Manifest feature flags (disproved):** the empty workspace feature names are intentionally repeated across first-party crates so a single `cargo --workspace --features ...` invocation can select the shared QA feature set. Removing them would break that compatibility surface; they are not crate-local feature implementations.
- **Showcase inspector allocations (disproved as a bug):** this diagnostic-only view deliberately materializes the current solved-tree snapshot during event-driven renders. It is outside the solver's allocation-free hot path, which has a dedicated 1,000-resize allocation contract; retaining row strings would add state and invalidation complexity without a measured user-facing benefit.
- **Duplicated debug traversal (disproved as a bug):** the recursive and flat solved representations have intentionally separate diagnostic walks. Both paths now have matching divider coverage; unifying them would obscure their different storage/layout invariants without correcting a behavioural defect.

Focused regression coverage covers the solver, macro, diagnostics, and showcase changes; `cargo test -p gpui-builder --features showcase` passes.

### High

- **Text-measure cache is keyed by trait-object address and lives forever — stale sizes after measure re-allocation (ABA).** `src/solver/misc.rs:24-34` + `src/solver/misc.rs:96-105`. `TextMeasureCache` persists prepared text and measured sizes in a thread-local default cache across all `solve()` calls, keyed by `measure.cache_key()`. The default `cache_key()` in gpui-pretext (`crates/gpui-pretext/src/measurement.rs:40-42`) is the instance's data pointer. If a `TextMeasure` is dropped and a different measure is later allocated at the same address (common for stack temporaries or per-frame recreated measures), the cache silently returns the *previous* measure's prepared text and sizes — wrong layout with no warning. The crate's own tests already work around this (`src/solver/tests.rs:109-110`: "avoid cache collisions from recycled trait-object addresses"), which confirms the hazard is live. Fix: in gpui-pretext, make the default key collision-safe (e.g. a global monotonically increasing id assigned per instance via a factory, or type-id + pointer + a creation counter); in gpui-builder, document that measures must be long-lived or override `cache_key()`, and consider exposing the default cache so callers can invalidate it.

### Medium

- **Chassis drops a "never collapse" (priority ≥ 1.0) section before its own guard runs.** `src/plugin_chassis/chassis_layout.rs:124-148`. The collapse loop marks the lowest-priority visible section invisible and *then* checks `all(visible have priority >= 1.0)` to break. When two or more priority-1.0 sections remain and their minimums still exceed `available_width`, the first of them is dropped before the guard fires — contradicting the field doc (`types.rs:43-44`, "1.0 = never collapses") and the in-code comment ("We accept clipping rather than dropping a never-collapse section"). Example: two priority-1.0 sections with min 200/280 at width 100 → the later one is collapsed instead of both being proportionally clipped by the existing clip path at line 196. Fix: restrict the `min_by` candidate set to `effective_priority(p) < 1.0` and break when no candidate remains (delete the post-drop guard).

- **`Fractional { min > max }` panics in `solve()` via `f32::clamp`.** `src/solver/child_info.rs:181`. `target.clamp(min, max)` panics when `min > max` (or either bound is NaN). `SlotNode` fields are public, so a hand-built `Sizing::Fractional` with inverted bounds reaches the solver directly; the check exists only in the opt-in `validate_layout` (`src/validation/validate.rs:214`), which `solve()` never calls. Fix: replace `clamp(min, max)` with a panic-free equivalent (`target.max(min).min(max)` — note this yields `min` when inverted, matching flex's min-floor behavior), or assert at the `Sizing::fractional` constructors and document the invariant.

- **Default thread-local text cache grows unboundedly and is not publicly clearable.** `src/solver/misc.rs:29-30` + `src/solver/misc.rs:60-69`. The `sizes` map is keyed by `(measure_key, cross_size.to_bits(), line_height.to_bits(), axis)`, so every distinct container width seen during a window resize adds a new entry per text node, and entries are never evicted. `TextMeasureCache::clear()` is public, but the default cache handle (`default_text_cache`) is `pub(super)`, so users of the plain `solve()`/`solve_tree()` entry points have no way to bound it. Fix: cap each per-key text map (e.g. LRU or a simple size cap with random eviction), stop including `cross_size` in the key for the horizontal path where it is unused, and/or expose a `clear_default_text_cache()` / return a handle from the entry points.

- **`solve_layout!` leaks the layout tree on every runtime evaluation.** `src/macros.rs:47-63` (and the nested `__gpui_builder_layout_declare_children!` at lines 87-93). Each invocation `Box::leak`s every child array and the root node to obtain `'static`; called inside any repeated code path (tests loop, debug pane, per-frame rebuild) it leaks memory without bound, and the macro docs do not mention it. Fix: build the tree in a local `Vec`/arena and solve by reference without leaking (the solver only needs `&LayoutNode<'a>` borrows that live for the call), or document prominently that each call leaks and the macro is for one-shot declarations.

### Low

- **Collapse pass can hide one more panel than necessary when `divider_size` is large.** `src/solver/child_info.rs:38-45` + `src/solver/child_info.rs:63-93`. `space_after_fixed` is computed once with the *initial* visible-child count; each solver collapse also frees one divider's worth of space, but the loop never re-accounts it, so in a marginal band (~`divider_size` wide per event) an extra collapsible panel is hidden even though it would fit. The post-loop divider recompute at lines 96-105 fixes the *allocation*, not the *decision*. Fix: subtract `divider_size` from the requirement inside the while loop (or recompute divider space per iteration).

- **User ratio overrides accept NaN/negative values and propagate NaN into solved sizes.** `src/types/layout_preferences.rs:44-46`, `src/state.rs:119-134`, consumed at `src/solver/child_info.rs:155,180`. A NaN ratio makes `fractional_demand` NaN (the `> 1.0` scale-down is bypassed) and yields a NaN `allocated_size` → NaN width/height in the solved tree; only the optional debug report flags it. Fix: clamp/validate ratios in `set_ratio` (`ratio.is_finite()` then clamp to `0.0..=1.0`) or sanitize in the solver before use.

- **Duplicate node ids silently overwrite each other in the flat tree's index.** `src/solver/solve.rs:470-471` (`push_solved_node`). `SolvedTree::find` then returns only the last node with that id while both remain in `nodes`; again only the opt-in `validate_layout` reports it. Fix: document the last-wins behavior on `solve_tree*`, or have the solver ignore/debug-assert duplicates.

- **Debug-report main-axis overflow ignores divider space.** `src/solved/layout_debug_warning.rs:184-189` and the duplicated flat-tree copy `src/solved/solved_tree.rs:471-476`. `used` sums only visible children, so a container whose children fit individually but whose children + dividers exceed the container is not flagged. Fix: add `divider_size * (visible_children - 1)` — this requires threading divider size into the report (currently absent from `SolvedNode`/`SolvedNodeData`).

- **Showcase: sidebar divider stays rendered/draggable when the sidebar is collapsed; inspector divider disappears.** `src/bin/layout_showcase/showcase_view.rs:496-502` (unconditional `divider_v("sidebar", ...)`) vs `showcase_view.rs:523-531` (inspector divider inside `.when(inspector.visible(), ...)`). In horizontal mode a collapsed sidebar leaves a live 6px divider that drags an invisible panel's ratio (click still toggles collapse back, presumably intentionally). Fix: pick one behavior — either render both dividers as restore affordances or gate both on visibility.

- **Showcase drag math uses container width as the ratio extent, but fractional ratios apply to post-fixed `distributable` space.** `src/bin/layout_showcase/showcase_view.rs:167-176` with `drag_extent = content_w` from `divider_v` (`showcase_view.rs:496-502`). Because the solver multiplies ratios by `distributable` (after fixed siblings and dividers), the pointer-to-ratio mapping is slightly off scale, more so when the inspector is collapsed. Fix: pass the solved `distributable` (e.g. content width minus the other panel's width and dividers) as the extent.

- **Showcase renders hardcoded dark colors and offers no keyboard/ARIA path for dividers or tree rows.** `src/bin/layout_showcase/showcase_theme.rs:15-25` ignores the active gpui-design theme (spacing/typography tokens are used, colors are not, and the crate's own `VisualColorScheme` manifest supports Light/Dark/HighContrast). Dividers (`divider_v`/`divider_h`, `showcase_view.rs:896-960`) and inspector tree rows (`showcase_view.rs:818-894`) are mouse-only: no `focus_handle`, no arrow-key ratio adjustment, no ARIA role/label — a gap vs the gpui-ui-kit components' accessibility pattern. Acceptable for a demo binary, but it is the crate's only interactive evidence, so the gap is visible in QA.

- **Dead feature flags in the manifest.** `crates/gpui-builder/Cargo.toml:33-46`: `autoeq`, `reqwest`, `spinorama`, `tokio`, `urlencoding` are declared as empty features with no dependencies and no `cfg(feature = ...)` uses in the crate — apparently vestiges copied from another crate. Fix: delete them.

- **Per-render allocation churn in the showcase inspector (demo-only).** `src/bin/layout_showcase/showcase_view.rs:727-739` rebuilds `Vec<VisualTreeRow>` with owned `String` ids plus `format!` labels per row on every render, and `debug_selector(|| "...".to_string())` closures allocate static strings (`showcase_view.rs:303,458`). Renders are event-driven (`cx.notify()`), so impact is small; reuse a rows buffer or intern ids if the inspector pattern is copied elsewhere.

- **Duplicated debug-report traversal logic.** `append_debug_node`/`collect_node_warnings` exist twice with near-identical bodies (`src/solved/layout_debug_warning.rs:99-222` for `SolvedNode`, `src/solved/solved_tree.rs:378-509` for `SolvedTree`) — the divider omission above already had to be noted in both. Consider sharing the walk over a common node-view trait to prevent drift.

## UI/UX consistency

The core crate is headless; only the `layout-showcase` binary renders UI. Findings above: hardcoded dark palette vs gpui-design theme tokens, inconsistent collapsed-divider behavior, slightly inaccurate divider drag scaling, and missing keyboard/focus/ARIA handling on dividers and tree rows relative to gpui-ui-kit conventions. Spacing, corner radii, and typography *do* consistently use `cx.design()` tokens.

## Clean bill

- No GPU/wgpu code anywhere in the crate (the showcase uses plain GPUI `div()` painting), so there are no readback/round-trip concerns. No async, mutexes, or channels; the only shared state is thread-local `RefCell` scratch pools, which are not held across awaits. One caution noted but not counted as a bug: `compute_text_size` (`src/solver/misc.rs:101`) holds `borrow_mut()` across the user-supplied `measure_width` callback — a measure that re-enters `solve` would panic; re-entrant measures seem implausible in practice.
- The allocation discipline in the solver hot path is genuinely good: `solve_tree_into` reuses the arena, id index, child-index pool, and text cache, and `tests/allocation_contracts.rs` enforces zero allocations over 1,000 warmed resize solves. The recursive `solve()` path documents its per-call allocation cost honestly.
- Determinism and overflow invariants are well tested (proptest recursive-vs-flat equivalence, no-overallocation property, tie-break tests, NaN-priority chassis test). Validation and debug-report machinery is thorough for an opt-in diagnostics layer.
