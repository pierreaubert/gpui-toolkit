# Bug Review: gpui-pretext — 2026-08-25

Scope: full scan of the `gpui-pretext` crate — the prepare phase (`src/analysis/*` segmentation/normalization/merging, `src/measurement.rs` cache, `src/layout/*` prepared-text construction), the layout phase (`src/line_break/*`: greedy walk, line counting, next-line cursor API, Knuth-Plass DP), plus `src/bidi/*`, `src/rich_text.rs`, `src/language_support.rs`, `Cargo.toml`, benches, and the integration tests under `tests/`. Roughly 36 source files / ~9.3k lines (of which ~2.6k are in-crate tests). The crate is headless (no GPUI rendering, no wgpu, no threads of its own — only thread-local `RefCell` scratch buffers), so the GPU and UI/UX sections are omitted. The three High findings were each reproduced with a scratch binary (`cargo run` against the crate by path) in addition to source reading; `cargo test -p gpui-pretext` passes (156 lib + 39 line_break + integration suites) as the baseline.

## Findings

Ranked by severity.

### High

- **`layout()` and `layout_with_lines()` disagree on line count when a space straddles the wrap point (simple fast path).** `src/line_break/count.rs:80-88` vs `src/line_break/walk.rs:191-197`. `count_prepared_lines_simple` handles an overflowing `Space` segment by silently dropping it and keeping the line open (`if is_simple_collapsible_space(kind) { continue; }`), while `walk_prepared_lines_simple` treats the same space as a break opportunity and emits the line (`can_break_after` → `emit_line!`). Concrete repro: text `"aaa b"`, widths 30/10/4, `max_width = 34` → `layout()` reports 1 line, `layout_with_lines()` produces 2 (`"aaa"`, `"b"`), and in debug builds `layout_with_lines` panics on its own consistency check (`src/layout.rs:89` `debug_assert_eq!(line_count, expected_line_count)` — verified panic: `left: 2, right: 1`). Since `layout()`'s `line_count * line_height` is what consumers use to size boxes, the count path under-reports height and text can be clipped. Fix: delete the duplicated counting logic and have `count_prepared_lines` call `walk_prepared_lines_simple(prepared, max_width, profile, None)` (it is already allocation-free), or make the count path mirror the walk's break-at-space semantics; add a golden case where the space itself straddles the boundary.

- **Soft-hyphen partial-fit lines render the hyphen before the fitted graphemes instead of after them.** `src/layout/misc.rs:119-131` (`build_line_text_into`). When a line ends mid-segment because a pending soft hyphen allowed fitting the first `fit_count` graphemes of the next word (`src/line_break/walk.rs:458-477`, `src/line_break/layout.rs:225-250`), the emitted width is `fitted_width + discretionary_hyphen_width`, i.e. the hyphen is the visual line end — but the text builder pushes `'-'` *before* the fitted graphemes. Repro: `"ab\u{00AD}cdefgh"`, 10px/char, 10px hyphen, `max_width = 50` → first line text is `"ab-cd"` (w=50) where it must be `"abcd-"`. The returned `LayoutLine.text` is both wrongly ordered and inconsistent with its own `width`. Fix: in the `end_graph > 0` branch, push the `skip..skip+take_count` graphemes first and the `'-'` after them; add a text-content assertion for a partial-fit soft-hyphen break (the existing test at `src/layout/tests.rs:265-282` only checks `line_count >= 2`).

- **Knuth-Plass multi-chunk fallback re-emits earlier chunks: duplicated lines and `line_count != lines.len()`.** `src/line_break/walk.rs:632-702`. `walk_prepared_lines_optimal` processes each hard-break chunk separately, invoking `on_line` as it goes; when a later chunk has no feasible KP solution (even after looseness recovery), it falls back with `return walk_prepared_lines(prepared, ...)` over the *entire* text — so all earlier chunks' lines are emitted a second time, while the returned count is only the greedy total. Repro: `prepare_with_segments("ok\n=====", PreWrap)` + `layout_with_lines_optimal` at `max_width = 20` (the non-word-like `"====="` run is unbreakable and infeasible for KP) → result has `line_count = 2` but `lines.len() = 3` with `"ok"` duplicated (greedy correctly returns 2/2). Any consumer iterating `.lines` renders the leading paragraphs twice. Fix: on fallback, restart cleanly — either drain/rewind the already-emitted lines before the greedy pass (e.g. truncate the caller's `lines` Vec to the length it had when the chunk loop started), or pre-scan all chunks for feasibility before emitting anything.

### High dispositions

- **Line-count divergence (2026-08-26): Fixed.** The simple count pass now closes an overflowing collapsible-space line exactly as the walker does, and its obsolete final `line_count + 1` branch was removed. Regression prepares the same text for both public layout APIs and asserts a two-line count, `line_count == lines.len()`, and preserved text output.

- **Partial soft-hyphen text order (2026-08-26): Fixed.** `build_line_text_into` now appends a discretionary hyphen after the fitted grapheme slice. Regression asserts that `ab\u{00AD}cdefgh` at 50px emits `abcd-`, matching the breaker's five-character width.

- **Optimal multi-chunk fallback (2026-08-26): Fixed.** Optimal chunk lines are buffered internally until every chunk succeeds. A later infeasible chunk now calls the greedy walker with the original callback and no prior output, preventing duplicate paragraphs. Regression covers `ok\n=====` and asserts `line_count == lines.len()` with one `ok` line.

### Medium

- **`seg_levels` is computed on every `prepare_with_segments` and never read.** `src/layout/types.rs:385-389` stores `compute_segment_levels(...)` into `PreparedCore.seg_levels`, which is marked `#[allow(dead_code)]` (`src/layout/types.rs:41-42`) and has no reader anywhere in the workspace. For any text containing a strongly-directional character this runs a full `unicode_bidi::BidiInfo::new` over the whole text, collects a per-char `Vec<i8>`, maps it per segment, and — via the single-entry cache in `src/bidi/mod.rs:148-158` — clones the levels vector twice and retains a full `String` copy of the normalized text in a thread-local. All of that work is discarded. Fix: either wire `seg_levels` into the layout API (the apparent intent) or stop computing it; if bidi metadata is kept, expose it on `PreparedTextWithSegments` so the cost is at least usable.

### Medium dispositions

- **Unused prepared bidi levels (2026-08-26): Fixed.** Removed `PreparedCore.seg_levels`, its bidi computation, and the no-longer-needed segment-start vector. The standalone bidi cache/helper remains tested; no public prepared-text API exposed the discarded metadata.

### Low

- **Dead `line_count + 1` branch in `count_prepared_lines_simple`.** `src/line_break/count.rs:94-96`. After the loop `has_content` can only be false when `widths` is empty, and that case returns early at line 31-33, so `return line_count + 1` is unreachable. If it were ever reached it would also double-count (the final non-empty line is already counted by `place_on_fresh_line`). Fix: remove it (best done together with the High finding above, which deletes this function's duplicated logic anyway).

- **`normalize_whitespace_normal` allocates even when nothing changes.** `src/analysis/normalize.rs:6-24`. `changed` is set for *any* whitespace character, so already-normalized text like `"hello world"` still takes the `Cow::Owned` path, and `String::with_capacity(text.len())` allocates up front before knowing whether a copy is needed — the `Cow::Borrowed` fast path only fires for whitespace-free input. Prepare-phase only, but it is the first thing that runs on every `prepare()`. Fix: track an actual mismatch (write index vs read index) and defer allocation until the first change, e.g. find the first whitespace run before allocating.

- **`layout_next_line` silently drops the segment when the cursor lands mid-segment on a non-breakable segment.** `src/line_break/layout.rs:112-140` (and the simple variant at lines 364-392): when `start_grapheme > 0` but `breakable_widths[i]` is `None`, the `!has_content` branch does nothing — the segment is neither appended nor measured and iteration moves on, so the returned line silently omits content (and `normalize_line_start` at `src/line_break/types.rs:152-154` explicitly passes such cursors through unvalidated). Cursors produced by the crate itself always point into breakable segments, so this needs a hand-built `LayoutCursor` to trigger, but the API is public and the failure is silent. Fix: clamp `grapheme_index` to 0 (or fall back to whole-segment placement) when the segment has no grapheme widths, or return `None`/document the precondition.

- **Module-wide warning suppression hides dead stores in the ported algorithm.** `src/lib.rs:41-42`: `#[allow(unused_assignments, unused_variables, unused_mut)]` on `pub mod line_break` suppresses warnings for the entire 2.4k-line algorithm module — exactly the module where a stale-state write would matter. Fix: remove the blanket allow and fix or individually annotate the remaining sites.

- **Hyphen-presence check differs between the width path and the text path.** `src/line_break/types.rs:846-852` (`breakpoints_to_lines`) adds `discretionary_hyphen_width` whenever `kinds[end_seg - 1] == SoftHyphen`, while `src/layout/misc.rs:62-71` (`line_has_discretionary_hyphen`) adds an extra `!(start_seg == end_seg && start_graph > 0)` exclusion. For a line that starts mid-segment and ends at that same segment's boundary after a soft hyphen, the width and the text would disagree about the hyphen. No producing call site was found for that cursor shape, so this is latent; worth unifying the two predicates (or sharing one helper) so the discrepancy cannot become live.

- **`PreparedText` is `!Sync` via the `RefCell` KP cache, undocumented.** `src/layout/types.rs:52`. `PreparedCore.kp_item_cache: RefCell<HashMap<...>>` makes both prepared-text types single-threaded to share; fine by design, but nothing in the README or rustdoc mentions that prepared text cannot be shared across threads (only moved). One doc line on `PreparedText` would prevent surprise compile errors in consumers.

### Low dispositions

- **Dead simple-count final branch (2026-08-26): Fixed** with the overflowing-space count correction above.
- **Normal whitespace allocation (2026-08-26): Fixed.** Already-normalized single interior spaces now return `Cow::Borrowed`; regression covers `hello world`.
- **Mid-segment non-breakable cursor (2026-08-26): Fixed defensively.** `normalize_line_start` clamps such a cursor to grapheme zero. Current preparation does not generate this state for visible non-breakable text, but future paths cannot silently drop it.
- **Module-wide warning suppression (2026-08-26): Fixed.** The root blanket allow was removed; the intentional ported state-machine assignment allowance is now scoped to only `line_break/layout.rs` and `line_break/walk.rs`, and stray `mut` bindings were removed.
- **Discretionary-hyphen predicate mismatch (2026-08-26): Fixed.** Text construction uses the same end-soft-hyphen predicate as width accounting; the soft-hyphen regression now checks both text and width.
- **Prepared text thread sharing (2026-08-26): Documented.** Both prepared-text handles now explicitly state their internal `RefCell` cache makes them non-`Sync`.

## Clean bill

- Threading: no mutexes, channels, or async anywhere; all shared state is thread-local `RefCell` scratch (`measurement.rs:14-21`, `line_break/types.rs:28-37`, `layout/misc.rs:13-16`, `bidi/mod.rs:76-83`). I traced the re-entrancy hazards: `knuth_plass_chunk` never drops a `KpBreaks` (whose `Drop` re-borrows `KP_BREAKS_SCRATCH`) while holding that borrow, and no user callback is invoked while a scratch borrow is held — no borrow-panic path found.
- Allocation discipline in the hot paths is genuinely good: the layout phase is arithmetic-only over cached widths, `layout_with_lines` pre-sizes the lines Vec from the count pass, `build_line_text_cow` borrows single-segment lines, grapheme/width scratch buffers are reused thread-locally, and `tests/allocation_contracts.rs` enforces zero allocations on warmed cache hits. The `MeasureCache` sentinel design (empty `Arc` for single-grapheme segments) avoids re-measure correctly.
- Panic paths: the production `unwrap()`s (`walk.rs:109,360,479`, `layout.rs:142,394`, `count.rs:44`, `get.rs:22`) are all guarded by `is_some()`/profile checks on the same data; `SegmentTexts` range integrity is guarded by `debug_assert`s at construction (`analysis/text_analysis.rs:15-27`) and the merge passes keep `starts` contiguous — no reachable out-of-bounds slice found. `parse_inline_markdown` (`rich_text.rs:97-171`) terminates on unclosed markers and borrows rather than copies.
- The Knuth-Plass DP itself (fitness classes, deactivation rule, flagged/fitness demerits, forced-break handling at `types.rs:633-643`) matches the standard formulation; `compute_adjustment_ratio` correctly excludes trailing glue. The KP item cache key (`types.rs:306-312`) correctly covers every parameter that affects item construction.
- `language_support.rs` is static, schema-versioned report data with a golden test (`locale_golden_cases_match_current_layout_output`) that pins real layout output — note it only exercises `layout_with_lines`, which is why the `layout()` count divergence above goes uncaught; extending that test to also assert `layout().line_count == expected_line_count()` would cover it.
