# MeshPlot implementation review

Date: 2026-08-10  
Reviewed branch: `feature/mesh-plot`  
Specification: `202060808-plot.md`

## Executive summary

`feature/mesh-plot` now implements most of the core model, 2D plotting path, retained WGPU 3D state, native interaction, Python IR/cache contracts, deterministic SVG, and a dedicated Metal 3D shader route. It is not yet production-ready because critical runtime, export, performance, and accessibility validation is still absent.

Estimated completion:

- Feature and API surface: approximately 75%.
- Strict acceptance and release criteria: approximately 50–55%.
- Overall: approximately 65%.
- Acceptance checklist: two complete items, seven partial items, and two unmet items.

The core mesh model, validation, topology, marching-triangle contours, adapter-backed isoline/filled-band preparation with CPU fallback, revolve generation, retained picking, Python schema/cache, 2D rendering, camera-projected SVG/PNG export, and the Metal 3D shader route are the strongest areas. GPU and offscreen 3D transforms now restore the f64 upload-rebase origin before camera projection. The principal gaps are orientation-triad/native visual coverage, asynchronous runtime evidence, adapter/embedded-viewport visual coverage, and release-quality performance/accessibility evidence. Drag-time LOD proxy rendering is implemented, but still needs native visual and performance evidence.

## Review findings and current status

The following records the original material risks, updated with the current branch state. The current action list below is authoritative.

### P0: native macOS 3D/revolve rendering lacks feature parity

The earlier blank-native-renderer risk is addressed: `MeshPlot` registers `MetalMeshRenderer::new_3d_with_camera` on macOS, with a dedicated normal-bearing raw vertex buffer, lit 3D MSL shader, camera view-projection, depth testing, explicit stage-uniform bindings, resize-aware textures, and a retained camera-oriented X/Y/Z triad overlay. The Metal feature explicitly enables the required 3D dependency rather than compiling a partial backend. Serialized Aqua-native tests now cover Surface3d and both full and partial revolves with depth-tested, substantially scalar-colored frames; a Surface3d wireframe-vs-fill framebuffer differential; a triangle with one near-clipped vertex that still produces a visible colored frame; and a 10,000-triangle profile that first renders the in-plot preparation status then renders the completed revolved surface. HiDPI and versioned-baseline coverage remains absent.

### P0: WGPU 3D embedded-viewport behavior needs adapter evidence

The attachment-size mismatch was fixed: custom draws receive the full target extent and preserve chart coordinates through viewport/scissor. The 3D renderer now intersects the physical chart rectangle with that target before setting either viewport or scissor, so partially clipped/offset layouts cannot submit out-of-range WGPU scissor coordinates. A headless adapter-backed rendered-frame test covers a negative-offset clipped chart, reuses the same retained custom draw after target resize, and issues two disjoint sibling viewport draws into the same target; it verifies that pixels outside charts and in the inter-chart gap retain already-rendered GPUI content. That test also exposed and corrected unsupported WGSL finite-value builtins, invalid line depth bias, an incompatible triad depth declaration, and full-frame MSAA-resolve clearing. The WGPU path now draws directly into the GPUI target with `Load` rather than resolving an intermediate full-frame MSAA color texture.

### P0: retained rendering is incomplete outside stable-geometry 3D updates

`MeshPlotState` now retains WGPU scene/custom-renderer/camera state, geometry revisions, surface BVHs, revolved geometry/BVHs, and derived fields. Regressions prove field/style-only and viewport/selection-only 3D updates keep topology/positions, geometry revisions, and geometry-upload counters unchanged; the viewport test also proves that the retained view transform changes for a zoom/resize. The live state now exposes a read-only retained-3D snapshot (scene identity, geometry revision, upload count, and upload bytes), and a serialized native resource test proves an unchanged freshly decoded 3D resource keeps that snapshot while a changed geometry generation replaces the scene and advances only geometry. Backend camera-only upload behavior has separate renderer coverage. Production timing telemetry remains open.

### P1: GPU compute integration is partial; complete asynchronous preparation still needs runtime evidence

`MeshCompute` now participates in retained MeshPlot isoline and filled-contour preparation when an adapter is available, including both stages of fill-plus-isoline mode. It receives an XY projection of the selected coordinate axes and preserves f64 public contour levels; adapter creation/dispatch failure falls back to the CPU marching-triangle path. GPU filled bands use per-source-triangle/per-level clipping and are reconstructed as triangle fans; differential tests compare exact band boundaries and area rather than f32 vertex coordinates. `MeshLodController` is connected to left/middle 3D drag gestures: it swaps a provenance-preserving proxy upload in at gesture start and restores the full upload at gesture end, while full-resolution picking and selection remain authoritative.

The retained GPUI owner runs contour and large axisymmetric-revolve preparation for meshes with 10,000 or more source triangles on the GPUI background executor. Revolve work prepares the derived mesh, BVH, and optional replicated field as one owned result keyed by geometry/field revision, source buffers, and the full revolve specification. Duplicate work is suppressed; stale completion is rejected; and a prior complete 3D scene remains visible while replacement geometry is prepared (the first large revolve uses a lightweight source-profile placeholder). Builder validation now performs only mesh/spec/radius checks, so it cannot synchronously derive a large revolved surface before that placeholder frame. Small charts remain synchronous.

### P1: retained owner and runtime accessibility evidence remain incomplete

`MeshPlot::build` now promotes the builder to a retained GPUI view, reused by the `(window, stable plot ID)` pair when a parent declaratively rebuilds it. Its interaction state is therefore retained across both parent patches and local notifications, so toolbar mutations and eventual asynchronous completion can redraw without reverting to the initial builder style. Declarative rebuilds classify geometry and field dirty domains from exact immutable content (including `f64` bit patterns for masked NaNs), rather than assuming fresh adapter-decoded `Arc` buffers are changes; a real changed field advances only the field revision, while a mesh or revolve-view change invalidates prepared geometry. The toolbar shares that state; Fit/Reset, wireframe, and automatic color-range reset are live, and individual actions can be hidden from layout/focus order. Render-mode menus offer only association-valid choices, the 3D view menu selects standard views or switches projection, and Export calls an application-provided callback with the current deterministic SVG (otherwise the action is disabled). Native 3D orbit, pan, zoom, fit/reset, cardinal/isometric views, projection switching, keyboard navigation, selection, and tooltip rendering are implemented. Runtime focus/menu and screen-reader QA remain open.

### P1: 3D/revolve SVG is present but export parity is incomplete

SVG now camera-projects depth-ordered surface and revolved triangles, wireframe edges, selection annotations, mesh-native isolines, and X/Y/Z orientation axes, using the retained camera or a deterministic fitted fallback. Homogeneous frustum clipping retains partially visible triangles, contour segments, and wireframe edges. A live-state regression proves SVG and PNG export do not mutate camera, selection, hover, viewport, or retained revisions. A serialized native Metal Surface3d/revolve regression rotates the fitted live camera, verifies a materially scalar-coloured live framebuffer, and then proves that SVG and caller-scale PNG consume that camera deterministically without mutating the live state. `MeshPlot::to_png(scale)` uses the offscreen fallback; direct native-framebuffer readback and pixel-identical renderer parity remain missing.

### P1: picking retention needs performance evidence

Surface BVHs, revolved geometry/BVHs, and derived revolve fields are retained by geometry/spec/field revision and source-buffer identity. Stable external-ID unit coverage exists; repeated-pick latency/allocation evidence is still missing.

### P1: live equal-aspect and remaining data-contract QA are incomplete

- Smooth scalar fills now require vertex fields and flat fills cell fields; mismatches yield structured validation errors.
- Explicit contour levels must intersect the displayed color range, and `MissingValuePolicy::MaskNaN` is implemented in Rust and transported through Python IR.
- SVG axes/grid/geometry use a common equal-aspect frame. Live GPUI pointer handling caches the painted plot bounds, converts window coordinates to local coordinates, and inverts the same letterboxed equal-aspect viewport used by the retained GPU scene; clicks, hover, and wheel zoom in letterbox bars are rejected. Wheel zoom now accepts an explicit data-space focal point rather than converting through the full rectangle. Native coverage deliberately targets a point whose visible and full-rectangle mappings fall in different triangles, then verifies the visible-triangle stable cell ID and hover before and after a real 600×400→800×400 window/chart resize. Keyboard zoom/pan remains covered.
- Resource-backed NaN values now reach `MaskNaN` and become explicit invalid-mask entries; resource-backed Infinity is rejected before retained-state mutation. Last-valid-frame rendering still needs explicit coverage.

### P1: Python runtime parity needs broader rendered-state proof

Python now defaults to equal aspect and supports automatic/fixed symmetric color ranges. Rust cache identity is centralized and the native cache rejects stale revisions before mutation, preserves a valid prior spec on invalid upsert, and drops inactive entries on `retain_only`.

The native MeshPlot runtime adapter now owns option conversion, inline/resource geometry, field, validity-mask, and stable-ID materialization, and the retained native element builder itself. Every native host therefore applies the same resource-shape, dtype, NaN/infinity, renderer-option, camera, selection, and colorbar behavior before it mutates retained state. The showcase delegates through a short compatibility shim pending deletion of its legacy local implementation. Serialized native Metal showcase-adapter regressions render a valid resource-backed plot, retain a newer valid field-resource generation as the last-valid spec, then apply missing geometry-resource generations and prove byte-identical fallback to that newest valid frame with the same retained `MeshPlotState` owner. Full Python-session coverage and renderer-upload instrumentation remain open.

### P1: QA evidence exceeds actual product coverage

The visual reference record acknowledges dirty provenance (`qa/visual/mesh-plot-reference.md:4`), and only the parent MeshPlot story has versioned viewport/theme entries. Runtime VoiceOver and Narrator testing remains incomplete.

The performance evidence is dirty or non-reference, and current benchmarks mostly mutate small state fixtures rather than exercising representative rendering, GPU upload, contour preparation, or 100k–10M vertex meshes.
