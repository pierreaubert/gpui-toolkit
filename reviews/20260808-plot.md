# Scientific mesh and field plotting for `gpui-toolkit`

**Date:** 2026-08-08
**Status:** Proposed
**Primary consumers:** Sonium 2D, axisymmetric, BEM, FEM, and field-map applications
**Toolkit surfaces:** `gpui-d3rs`, `gpui-px`, `gpui-python-runtime`, and `gpui-ui-kit`

## 1. Decision summary

Add a high-level `MeshPlot` component to `gpui-px`, backed by reusable
unstructured-triangle algorithms and rendering in `gpui-d3rs`, with equivalent
Python declarations and patch support in `gpui-python-runtime`.

`MeshPlot` is the missing bridge between the toolkit's existing chart and 3D
scene capabilities. It must render:

- a bare 2D or 3D triangle mesh;
- a scalar variable associated with mesh vertices or cells;
- smooth vertex shading or flat cell shading;
- filled contour bands and isolines on an unstructured 2D mesh;
- an axisymmetric `r-z` result as either a 2D section or a revolved 3D surface;
- a triangle surface mesh in an interactive 3D view;
- axes, units, a colorbar, a compact plot toolbar, inspection, and export.

The first release is a scientific result viewer, not a general CAD or volume
visualization system. It accepts indexed triangles. Tetrahedral slicing,
volume rendering, iso-surfaces, streamlines, vector glyphs, and high-order
curved elements are follow-up work.

## 2. Why a new component is needed

The current toolkit already contains useful pieces:

- `gpui-px::heatmap`, `contour`, and `isoline` render scalar values on a dense
  rectilinear grid;
- `gpui-px::surface3d` renders `z = f(x, y)` on a dense grid;
- retained `scene3d::MeshSpec` renders indexed triangles with per-vertex or
  per-cell scalar values and keeps geometry, material, and camera caches
  separate;
- the Python runtime exposes regular-grid charts and retained 3D mesh scenes.

Those pieces do not provide one path for an unstructured solver mesh. In
particular, the regular-grid contour generator cannot consume FEM/BEM
connectivity, while `scene3d::MeshSpec` does not provide a 2D scientific plot
frame, unstructured contours, an integrated colorbar, or a complete picking
event. Applications therefore export VTU and switch to ParaView/PyVista or
build bespoke plots.

`MeshPlot` must compose and extend the current primitives. It must not create a
second color system, camera implementation, or unrelated chart framework.

## 3. Product outcome

A simulation application is sufficient when a user can run a solve and, in
the same GPUI window:

1. inspect the generated mesh before solving;
2. choose a scalar result and see it over the mesh;
3. switch between fill, filled contours, isolines, and wireframe overlays;
4. inspect coordinates, cell/vertex identity, and the displayed value;
5. pan and zoom a 2D or axisymmetric section;
6. orbit, pan, zoom, reset, and fit a 3D surface;
7. update only the result field without losing the view or re-uploading the
   mesh;
8. export the displayed view for reports while retaining VTU/ParaView as an
   advanced interchange path.

## 4. Scope for the first release

### 4.1 Required views

| View | Required input | Required output |
|---|---|---|
| 2D mesh | 2D/3D positions plus triangle indices | wireframe, boundaries, equal-aspect axes |
| 2D scalar field | mesh plus vertex or cell scalar values | smooth/flat fill, colorbar, optional wireframe |
| 2D filled contour | mesh plus vertex scalar values | deterministic filled bands on triangles |
| 2D isolines | mesh plus vertex scalar values | deterministic lines at explicit or automatic levels |
| Axisymmetric section | triangular mesh interpreted as `r-z` | 2D result with radial/axial labels and nonnegative-radius validation |
| Axisymmetric revolve | axisymmetric section plus sweep settings | generated 3D triangle surface with replicated scalar field |
| 3D surface | 3D positions plus triangle indices | shaded surface, scalar colors, wireframe, camera, colorbar |

The existing `line`, `scatter`, regular-grid `heatmap`, `contour`, `isoline`,
and `surface3d` builders remain public. `MeshPlot` is for topology-aware data;
it does not replace normal 1D response plots or efficient rectilinear grids.

### 4.2 Explicit non-goals

- Parsing VTU, VTK, Gmsh, Exodus, or Sonium-specific types in gpui-toolkit.
- Moving result projection, solver state, or physics conventions into the UI.
- Rendering tetrahedra, hexahedra, or arbitrary polyhedra directly.
- Interior volume slices, volume ray casting, or 3D iso-surfaces.
- Vector arrows, streamlines, tensor ellipsoids, or particle traces.
- Mesh editing, node dragging, remeshing, or boundary-condition assignment.
- High-order curved geometry or high-order field interpolation.
- A timeline/animation editor. Field replacement is sufficient for an
  application-owned time or frequency selector.

## 5. Canonical data model

The renderer-facing model belongs in `gpui-d3rs`; `gpui-px` owns the ergonomic
builder and plot frame; the Python runtime maps its versioned schema onto the
same concepts.

Representative Rust API:

```rust
use std::sync::Arc;

pub struct TriangleMesh {
    pub id: Arc<str>,
    pub positions: Arc<[[f64; 3]]>,
    pub triangles: Arc<[[u32; 3]]>,
    pub vertex_ids: Option<Arc<[u64]>>,
    pub cell_ids: Option<Arc<[u64]>>,
}

pub struct ScalarField {
    pub id: Arc<str>,
    pub label: Arc<str>,
    pub unit: Option<Arc<str>>,
    pub values: Arc<[f64]>,
    pub association: ScalarAssociation,
    pub valid: Option<Arc<[bool]>>,
}

pub enum ScalarAssociation {
    Vertex,
    Cell,
}

pub enum MeshPlotView {
    Planar { horizontal: CoordinateAxis, vertical: CoordinateAxis },
    AxisymmetricSection { radial: CoordinateAxis, axial: CoordinateAxis },
    AxisymmetricRevolve(RevolveSpec),
    Surface3d,
}

pub enum MeshRenderMode {
    Mesh,
    ScalarFill { interpolation: FieldInterpolation },
    FilledContours { levels: ContourLevels },
    Isolines { levels: ContourLevels },
    FillAndIsolines { levels: ContourLevels },
}

pub fn mesh_plot(mesh: TriangleMesh) -> MeshPlot;
```

`TriangleMesh` is deliberately independent of FEM, BEM, ndarray, NumPy, and
`num_complex`. A consumer converts its domain mesh once. Scalar values are
always real at the toolkit boundary.

For complex, vector, or tensor solver output, the producer selects the scalar
quantity before updating the plot. Examples include real part, imaginary part,
magnitude, phase, sound-pressure level, vector magnitude, or one tensor
component. The field label and unit must describe that projection. This keeps
reference values, phase conventions, and domain-specific units out of the UI
crate.

### 5.1 Geometry rules

- Positions use `f64` at the API boundary and are normalized before conversion
  to GPU `f32`, so large offsets do not destroy local display precision.
- Triangle winding controls the front face in 3D. The default material is
  two-sided because many BEM meshes are viewed from both sides.
- Indices are zero-based `u32` and every index must be in range.
- Zero-area and repeated-index triangles are rejected by default. A diagnostic
  mode may skip them and report a count, but must not fail silently.
- Optional external vertex and cell IDs are returned by picking. Array indices
  are used when external IDs are absent.
- Quads and volume-cell boundary extraction are producer responsibilities in
  v1. A later toolkit helper may add deterministic triangulation without
  changing `TriangleMesh`.

### 5.2 Field rules

- A vertex field has exactly one value per position. A cell field has exactly
  one value per triangle.
- Vertex fields support smooth fill, filled contours, and isolines. Cell
  fields support flat fill only in v1.
- Requesting contours for cell data returns a structured
  `ContoursRequireVertexField` error. The toolkit must not invent a nodal
  reconstruction rule.
- Coordinates and unmasked field values must be finite. Missing data uses an
  explicit validity mask. `NaN` and infinities are rejected unless the caller
  explicitly selects `MissingValuePolicy::MaskNaN`; infinities are never
  accepted as drawable values.
- A constant field renders one color, a valid constant range, and no isolines.
- Geometry, field, style, camera, selection, and viewport have independent
  revisions and cache keys.

## 6. Plot configuration

`MeshPlot` must expose the normal `gpui-px` builder conventions: `title`,
`size`, `fill`, `min_size`, `aspect_ratio`, `design`, `build`,
`accessibility_summary`, and deterministic export.

It additionally requires:

```rust
mesh_plot(mesh)
    .field(field)
    .view(MeshPlotView::Planar {
        horizontal: CoordinateAxis::X,
        vertical: CoordinateAxis::Y,
    })
    .mode(MeshRenderMode::FillAndIsolines {
        levels: ContourLevels::Count(12),
    })
    .color_scale(ColorScale::Viridis)
    .color_range(ColorRange::Auto)
    .colorbar(Colorbar::new("Sound pressure level").unit("dB SPL"))
    .wireframe(Wireframe::overlay())
    .axes(Axes2d::equal_aspect().labels("x", "y").unit("m"))
    .interactions(PlotInteractions::inspect_and_navigate())
    .build()?;
```

### 6.1 Color and levels

- Reuse the existing gpui-px sequential and diverging color scales.
- The default is `Viridis`; signed fields should be able to select `CoolWarm`
  with a symmetric range about zero.
- `ColorRange` supports `Auto`, `Fixed { min, max }`, and
  `Symmetric { center, extent: AutoOrFixed }` in v1.
- Linear color mapping is required. Log and symmetric-log color mapping may be
  added later; applications can pre-transform values today.
- Automatic contour levels use a documented nice-number algorithm over the
  displayed color range. Explicit levels must be finite, strictly increasing,
  unique, and within or intersecting the display range.
- The colorbar displays label, optional unit, range, and ticks. It is never
  encoded as a fake chart axis.

### 6.2 Axes and aspect

- Planar and axisymmetric plots default to equal data aspect so a metre in one
  direction is not visually stretched relative to a metre in the other.
- Users may opt into fill-aspect for dashboard layouts.
- Axes provide title, coordinate label, unit, ticks, grid visibility, and an
  explicit or automatic range.
- Physical mesh coordinates use linear axes in v1.
- Axisymmetric sections default to `r` horizontally and `z` vertically. Radius
  values below a configurable numerical tolerance are rejected.
- 3D views show a compact orientation triad and optional bounds/axis labels;
  the scalar colorbar remains a 2D overlay.

## 7. Rendering behavior

### 7.1 Unstructured 2D

The 2D path must render in data coordinates and clip to the plot rectangle.
Wireframe edges are deduplicated, so shared triangle edges are not painted
twice with different opacity.

Vertex scalar fill uses barycentric interpolation. Cell scalar fill uses one
flat value per triangle. Masked triangles are transparent and do not
participate in contour generation or inspection.

Filled bands and isolines use marching-triangle operations, not resampling to
a rectangular grid. Edge intersections must be computed once per shared edge
and level, or with an equivalent deterministic rule, so neighboring triangles
cannot produce cracks. Exact-on-level vertices and edges require a documented
tie break. Filled band clipping must preserve holes and domain boundaries.

### 7.2 Axisymmetric revolve

`RevolveSpec` includes the radial and axial coordinate axes, start angle, sweep
angle, and segment count. The default is a full `2π` sweep with 64 segments.

The generated surface is a retained derivative of the 2D geometry:

- changing only the scalar field must not rebuild its positions or indices;
- vertex fields repeat at each angular segment;
- cell fields repeat for the derived triangles;
- vertices on the axis are collapsed without emitting degenerate triangles;
- partial sweeps include end caps only when explicitly requested;
- normals are smooth around the sweep and respect the source triangle
  orientation.

### 7.3 3D surface

The 3D path reuses retained Scene3D mesh buffers, camera state, depth testing,
materials, colormaps, and orbit/pan/zoom behavior. `MeshPlot` adds the plot
frame, colorbar, toolbar, selection event, and consistent field/geometry patch
semantics.

Vertex fields render smoothly and cell fields render flat. A wireframe overlay
must remain legible in light, dark, and high-contrast themes. Lighting changes
surface shape perception but must not change the scalar-to-color mapping.

## 8. Interaction and state

All camera and pointer navigation is native and must not require a Python round
trip.

### 8.1 Required interactions

- 2D: wheel/pinch zoom, drag pan, box zoom, reset, fit, hover inspect, click
  select, and keyboard equivalents.
- 3D: orbit, pan, zoom, reset, fit-to-bounds, standard orthogonal views,
  hover inspect when enabled, and click select.
- Toolbar: fit/reset, render-mode menu, wireframe toggle, color-range reset,
  projection/view menu, and export. Applications may hide the toolbar or
  individual actions.
- View state survives field, colormap, title, and color-range patches. Geometry
  replacement resets or fits the view only when requested or when the old view
  does not intersect the new bounds.

### 8.2 Inspection result

A pick produces a typed result:

```rust
pub struct MeshPlotPick {
    pub plot_id: Arc<str>,
    pub mesh_id: Arc<str>,
    pub cell_index: u32,
    pub cell_id: Option<u64>,
    pub nearest_vertex_index: Option<u32>,
    pub vertex_id: Option<u64>,
    pub world_position: [f64; 3],
    pub displayed_value: Option<f64>,
    pub field_id: Option<Arc<str>>,
}
```

The native tooltip shows formatted coordinates, external ID when present,
field label, value, and unit. For a vertex field it reports the barycentrically
interpolated value at the hit point; for a cell field it reports the cell
value. Python receives selection changes, not every hover movement.

## 9. Python API and protocol

Python parity is part of v1, not a later wrapper exercise. Add a typed
`gpui_toolkit.meshplot` module and `ui.mesh_plot(spec, ...)` node. A
representative application API is:

```python
from gpui_toolkit import meshplot, ui

geometry = meshplot.geometry(
    id="baffle",
    positions=positions,
    triangles=triangles,
    cell_ids=element_ids,
)

pressure = meshplot.scalar_field(
    id="pressure-db",
    values=pressure_db,
    association="vertex",
    label="Sound pressure level",
    unit="dB SPL",
)

plot = meshplot.plot(
    id="pressure-field",
    geometry=geometry,
    field=pressure,
    view="planar",
    mode="fill_and_isolines",
    contour_levels={"count": 12},
    color_scale="viridis",
    equal_aspect=True,
    interactions=["pan", "zoom", "inspect", "select", "reset", "fit"],
)

ui.mesh_plot(plot, selection_action="inspect-result")
```

The schema is versioned independently from the general app IR. Unknown future
versions, topology names, associations, modes, or color scales produce a
localized structured error instead of a host panic.

Geometry, indices, scalar values, masks, and optional IDs may be inline for
small examples. Production data must also accept typed `Resource` handles.
The portable resource formats are little-endian `f32`/`f64` for coordinates
and values, `u32` for indices, `u64` for external IDs, and packed or byte
booleans for masks. Payloads over the configured inline threshold use the
existing bounded resource transport instead of JSON decimal arrays.

Required patch operations are:

- replace geometry and topology together;
- replace one field's values or validity mask;
- change the active field, mode, contour levels, range, or colormap;
- change labels and units;
- set/reset camera and 2D viewport;
- set/clear selection;
- drop stale resources.

Patches are revisioned. Late field updates must not overwrite a newer result,
and a stale or evicted resource returns a recoverable error containing the
plot, resource, generation, and patch IDs.

## 10. Ownership and crate boundaries

### `gpui-d3rs`

- Canonical indexed-triangle and scalar-field render data.
- Mesh validation, bounds, unique edges, adjacency, barycentric hit testing,
  marching triangles, band clipping, isoline stitching, and revolve geometry.
- CPU preparation caches plus GPUI/GPU render elements.

### `gpui-px`

- `MeshPlot` builder and error mapping.
- Axes, colorbar, title, responsive sizing, design-system defaults,
  accessibility summary, interaction state, and static export.
- Composition with existing `ColorScale`, chart sizing, interaction, and
  capability-report infrastructure.

### `gpui-python-runtime`

- Versioned Python dataclasses and Rust IR types.
- Validation, capability negotiation, resource references, revisioned patches,
  and typed selection events.
- Retained cache mapping that preserves native camera and selection state.

### `gpui-ui-kit`

- Reusable compact plot toolbar, tooltip/popup treatment, focus behavior, and
  accessible controls.
- No solver, mesh, contour, or scalar conversion logic.

### Application/Sonium

- Adapting FEM/BEM/field-map data into triangles and scalar arrays.
- Selecting complex/vector/tensor projections and assigning correct units.
- Choosing the active result, time, frequency, or eigenmode.
- Exporting VTU or other domain artifacts and owning durable result storage.

## 11. Validation and failure behavior

Validation happens before retained resources or GPUI state are mutated. At a
minimum, errors distinguish:

- empty positions, triangles, or field arrays;
- non-finite coordinates or unmasked values;
- index out of range and invalid index count;
- repeated-index or zero-area triangles;
- vertex/cell field length mismatch;
- mask length mismatch;
- invalid radius in axisymmetric mode;
- invalid revolve sweep or segment count;
- invalid, unsorted, or duplicate contour levels;
- contour requested for a cell field;
- invalid color range or range incompatible with the field;
- stale resource generation, unsupported dtype, shape, or byte order;
- unsupported schema version or capability.

A bad field patch leaves the last valid plot visible with a local error state.
It must not clear retained geometry, reset the camera, or crash the host.

## 12. Accessibility and theming

- Colors, fonts, spacing, focus rings, tooltips, and toolbar controls come from
  `gpui-design`/`gpui-ui-kit`.
- Default color scales must remain interpretable under the supported color
  vision deficiencies. No result may rely only on red versus green.
- High-contrast mode increases mesh/line contrast and supplies a colorbar
  border without changing numeric mapping.
- The plot is one focusable image/graphic with a structured accessibility
  summary: title, view, vertex/triangle counts, field label/unit, finite range,
  association, selected item, and available controls.
- Toolbar actions are keyboard reachable. Keyboard pan, zoom, fit, reset, view
  changes, and selection traversal have documented bindings.
- The host accessibility bridge receives the same summary. Product-level
  screen-reader QA remains required before claiming full OS parity.

## 13. Export

- 2D mesh, scalar, contour, and isoline views export deterministic SVG with
  axes, title, colorbar, selected annotation, and the displayed viewport.
- 3D and revolved views export a deterministic projected SVG and, where the
  host supports framebuffer capture, PNG at a caller-selected scale.
- Export uses the current camera/view and the exact displayed range and levels.
- Export does not mutate interaction state.
- Raw numeric and VTU/VTK export remain application responsibilities. The plot
  must expose enough metadata for the application to offer those actions next
  to the toolkit's image/vector export.

## 14. Performance and resource requirements

- Geometry and topology are uploaded once and retained until their revision
  changes. A scalar-only update must not rebuild adjacency, unique edges,
  revolved geometry, normals, or camera state.
- A camera-only frame performs no contour generation, geometry hashing, JSON
  parsing, or buffer upload.
- Prepared 2D contours are cached by geometry revision, field revision, mask,
  level set, and interpolation policy.
- Large arrays use shared/retained resources. Resource caches have a byte
  budget, observable statistics, reference counts, and deterministic eviction.
- The render thread never waits for Python, file I/O, mesh conversion, contour
  generation above the synchronous work threshold, or export encoding.
- Expensive contour/revolve preparation runs off the render thread and swaps a
  complete revision atomically. The old valid frame remains visible meanwhile.

Release benchmarks must record, on the standard desktop QA machine:

- initial display and fit for 100,000 vertices / 200,000 triangles;
- field-only replacement for 100,000 vertex values;
- 12-level filled contours and isolines for 100,000 triangles;
- sustained camera navigation after upload;
- peak retained CPU/GPU bytes and allocations after warm-up.

The acceptance target is 60 Hz camera navigation on the reference machine,
no per-frame geometry upload during navigation, and no unbounded growth during
1,000 alternating field updates. Numeric preparation timings are recorded as
release evidence rather than asserted identically across platforms.

## 15. Required tests

### Algorithms and validation

- Single triangle, two shared triangles, square, hole, disconnected islands,
  saddle field, constant field, masked triangle, exact-on-level vertex/edge,
  and reversed winding.
- Analytically known linear fields where isolines are straight and the
  barycentric interpolant is exact.
- Shared-edge crack checks for every contour level.
- Vertex/cell association and every validation error listed above.
- Full and partial axisymmetric sweeps, vertices on the axis, and scalar
  replication.
- Deterministic output independent of triangle input order where topology and
  IDs describe the same mesh.

### Rendering and interaction

- Light, dark, and high-contrast visual baselines at dashboard, panel, and
  narrow/mobile widths.
- Mesh-only, smooth fill, flat fill, filled contours, isolines, combined mode,
  axisymmetric section/revolve, and 3D surface stories.
- 2D and 3D picking against known cells and values.
- Camera/viewport and selection preservation across field/style patches.
- Geometry replacement invalidation and fit policy.
- Keyboard operation, focus order, accessibility summary, and bridge snapshot.
- SVG determinism and displayed-range/level parity.

### Python and protocol

- Golden round trips for inline and resource-backed geometry, fields, masks,
  IDs, configuration, and pick events.
- Capability negotiation, future-schema rejection, stale revisions, stale
  resources, malformed shapes/dtypes, and oversized inline payloads.
- Field-only patch proves the geometry fingerprint/upload is unchanged.
- Rapid frequency/time updates prove late results cannot replace newer state.
- Resource eviction and explicit drop leave no retained leak.

### Performance

- Benchmark mesh preparation, contours, revolve, hit testing, uploads, field
  replacement, and camera-only frames at small/medium/large sizes.
- Allocation contract for navigation after warm-up.
- Cache-size and 1,000-update bounded-memory contract.

## 16. Capability reporting

Extend the existing gpui-px capability and visual-regression reports with a
new public story, `px.mesh_plot`, and separate entries for:

- unstructured triangle mesh rendering;
- vertex/cell scalar fields;
- unstructured filled contours and isolines;
- axisymmetric section and revolve;
- retained field-only updates;
- picking and native navigation;
- Python/resource parity;
- static export and accessibility.

No entry is `Implemented` solely because an algorithm exists. It requires its
focused tests, component-lab story, and the applicable runtime QA evidence.

## 17. Delivery sequence

1. **Shared model and algorithms:** add `TriangleMesh`, field validation,
   bounds/edges/adjacency, marching triangles, hit testing, and revolve logic
   to `gpui-d3rs` with deterministic unit tests.
2. **2D `MeshPlot`:** add the gpui-px builder, axes, colorbar, wireframe,
   scalar fill, contours, isolines, inspection, accessibility, and SVG export.
3. **3D composition:** reuse Scene3D buffers/camera for surfaces and revolved
   meshes; add the plot overlay, toolbar, picking, and cache assertions.
4. **Python parity:** add versioned declarations, `ui.mesh_plot`, resource
   arrays, patches, capability negotiation, and selection events.
5. **Product hardening:** add component-lab stories, cross-theme visual
   baselines, reference-machine benchmarks, memory profiling, and Sonium smoke
   examples for 2D, axisymmetric, BEM surface, and regular field-map results.

The first product integration should use a small 2D triangular scalar field
and a 3D BEM surface. Axisymmetric revolve follows within the same feature
release after the 2D data and cache contracts are stable.

## 18. Acceptance checklist

The feature is complete when all statements below are true:

- [ ] One public Rust builder renders mesh-only, vertex-field, and cell-field
  triangle data in 2D and 3D.
- [ ] The same 2D mesh renders filled contours and isolines without conversion
  to a rectangular grid.
- [ ] Axisymmetric `r-z` data renders as a section and a retained revolved
  surface.
- [ ] Axes, equal aspect, labels, units, color range, colorbar, and wireframe
  behave consistently across views.
- [ ] Native navigation and inspection work, and selection produces a typed
  stable-ID event.
- [ ] Field/style updates preserve geometry, camera/viewport, and selection.
- [ ] Python can declare and patch the same feature with inline and retained
  resource data.
- [ ] Invalid input yields a localized structured error and leaves the last
  valid frame intact.
- [ ] Deterministic export, accessibility summaries, visual baselines, and
  capability-report evidence are present.
- [ ] Reference benchmarks show bounded memory and no geometry re-upload during
  camera-only or field-only updates.
- [ ] Sonium examples no longer require an external viewer for routine 2D,
  axisymmetric, contour, or 3D surface result inspection.
