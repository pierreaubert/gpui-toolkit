# Plan: make Vello the default 2D renderer

## Goal

Make Vello the default renderer for ordinary 2D graph marks in `gpui-d3rs` and
`gpui-px`, and for custom-painted audio visuals in `gpui-audio-kit`. The d3rs,
px, and UI-kit showcases must visibly exercise that default. Legacy `gpu2d`
rendering remains an explicit escape hatch and a parity reference, not the
normal path.

This plan starts from the current dirty worktree. It already contains a
`Renderer2D`/`VelloBackend` split, Vello CPU/WGPU scene painters, several chart
and audio producer integrations, renderer selectors in the showcases, visual
manifest/gallery plumbing, and the first UI-kit Audio Visuals section. Preserve
unrelated staged and unstaged work while completing and verifying the gaps
below.

## Scope and non-goals

In scope:

- The renderer contract and fallback behavior in `gpui-d3rs`.
- Shared validated geometry and dispatch for d3rs and px marks.
- Vello-backed spectrum, meters, potentiometer, and volume-knob paints.
- Native and WASM showcase selection, renderer metadata, manifests, and
  screenshot coverage.
- Deterministic CPU fixtures and lifecycle/allocation instrumentation that can
  run without a GPU.

Out of scope:

- Moving layout, text, axes, legends, accessibility, hit testing, or interaction
  state into Vello; existing GPUI/chart models remain responsible for those.
- Changing static SVG export, low-level `gpu2d` readback APIs, or their explicit
  legacy examples.
- Treating `MeshPlot`, `gpu3d`, Surface3D, force, sphere, or other 3D demos as
  2D Vello coverage.
- Introducing a second visual-test/component-lab framework. Extend the current
  manifests, screenshot scripts, and WASM gallery.

## Current architecture and invariants

The implementation should preserve these invariants while filling the gaps:

1. `gpui_d3rs::render2d::Renderer2D::{Vello, Legacy}` is the high-level mark
   choice. With the Vello feature enabled, `Renderer2D::default()` is `Vello`;
   feature-off builds continue to compile and use `Legacy`.
2. `VelloBackend::{Auto, Wgpu, Cpu}` is the low-level Vello backend choice.
   `Auto` prefers the WGPU custom-draw path and falls back to CPU image
   painting when custom draw is unavailable or fails. Explicit `Cpu` and
   `Wgpu` must not silently change meaning.
3. `vello2d::RasterBackend` remains a compatibility alias. Existing
   `raster_backend` call sites continue to compile while new code uses
   `vello_backend`.
4. Geometry, validation, scales, NaN/empty handling, picking, accessibility
   summaries, and chart semantics are shared by Vello and Legacy. Only the
   paint submission differs.
5. Audio elements own one persistent painter. Renderer/backend setters mutate
   that painter; they must not configure a temporary painter and then discard
   it.
6. WASM code must not block on `pollster`, synchronous `device.poll`, or
   synchronous GPU readback. Deferred `map_async` readback remains the browser
   contract.

## Workstream 1: finish the shared renderer and painter contract

### API and feature behavior

Implement and test the public contract in `crates/gpui-d3rs/src/render2d.rs`
and `crates/gpui-d3rs/src/vello2d/`:

- Keep the Vello default and explicit Legacy escape hatch documented in the
  type-level API and crate README.
- Keep Vello code behind the existing `vello`/`vello-gpui` features. A
  no-default-features build must not reference Vello-only symbols.
- Preserve compatibility setters and make every px chart builder and audio
  builder expose the same renderer/backend choice and chaining behavior.
- Decide and document the unavailable-feature policy: fallible px builders
  should return a typed renderer-unavailable error when Vello is explicitly
  requested but not compiled; infallible audio constructors should safely fall
  back to Legacy.

### `VelloScenePainter` state machine

Document the state transitions in `vello2d/element.rs` and implement any missing
pieces:

- Resolve `Auto` once per element/device, rather than changing backend on every
  paint.
- Reuse a same-size CPU rasterizer, WGPU custom-draw registration, scene, and
  image when the scene revision and bounds are unchanged.
- Recreate only size-dependent targets when width, height, scale factor, or
  device changes.
- Unregister a failed WGPU custom draw before switching to CPU; never leave a
  stale registration alive.
- Drop superseded GPUI `RenderImage`s through the owning `Window` before
  replacing them.
- Make empty scenes, zero/negative bounds, transparent output, and resize-only
  paints explicit no-op or clear behavior.
- Ensure `Drop` unregisters custom draw and releases CPU/WGPU resources exactly
  once.
- Add test-only counters/hooks for rasterizer/pipeline creation, registration,
  unregistration, scene submissions, resizes, image drops, and fallback
  transitions. Keep the hooks out of release builds.

### Scene primitive completeness

Complete the common scene representation in `vello2d/scene.rs` and WGPU upload
path for the primitives used by the producers:

- filled and stroked paths;
- rectangles and rounded rectangles;
- circles and points;
- wedges/arcs and ring segments;
- clipping, opacity, and brush/color reuse.

Keep bounds and coordinate conversion deterministic so CPU fixtures and WGPU
captures consume identical scene data.

## Workstream 2: route all ordinary chart marks through one dispatch path

Create one selection/dispatch helper per mark family. Producers should build
validated normalized geometry once and pass it to either Vello or the explicit
Legacy adapter; showcase cards must not duplicate geometry logic.

### d3rs marks

Audit library and showcase paths for direct `gpu2d::shapes` construction and
route ordinary stories through Vello by default:

- line and area-like paths;
- bars and grouped bars;
- scatter;
- heatmaps;
- contour bands and isolines.

Keep low-level `gpu2d_*` demos and LOD scatter explicitly Legacy until an
equivalent Vello implementation is intentionally designed. Label those demos
as Legacy so they cannot be mistaken for default coverage.

### px marks

Apply the same dispatch contract to:

- line and area;
- bar and grouped/category bars;
- boxplot;
- pie and donut;
- treemap;
- heatmap;
- contour and isoline;
- ordinary scatter and matrix/scatter diagnostics.

Preserve validation errors, scales (including reversed and logarithmic axes),
NaN handling, normalized geometry, picking, legends, accessibility metadata,
and resize/high-DPI behavior across both renderers. `MeshPlot` remains outside
this 2D migration.

## Workstream 3: migrate custom audio paints

Complete and review the Vello scenes in `gpui-audio-kit`:

- `spectrum/spectrum_element.rs`: bars/fills, threshold bands, grid/clip
  behavior, and stable empty-data output;
- `meter.rs`: vertical and horizontal segments, peak/hold lines, clipping,
  and consistent orientation handling;
- `audio/potentiometer/knob_arc_element.rs`: arc/track and value stroke;
- `audio/potentiometer/tick_element.rs`: tick marks and endpoint behavior;
- `audio/volume_knob/volume_knob_fill_element.rs`: background, value fill,
  ring, and mute/disabled states.

Keep smoothing, interaction, keyboard/mouse behavior, formatting, and
accessibility in the existing audio components. Make default constructors
select `Renderer2D::Vello` and `VelloBackend::Auto`; retain explicit CPU and
Legacy setters for constrained hosts and QA. Ensure all elements keep their
painter in component state and that warmed updates do not allocate or register
custom draw repeatedly.

## Workstream 4: showcases, selectors, and release metadata

### d3rs showcase

- Route line, bars/grouped bars, scatter, heatmap, contour, isoline, and normal
  D3 examples through the same library dispatch helpers.
- Leave force/3D/low-level gpu2d examples on their documented legacy path.
- Support stable native `D3RS_SHOWCASE_RENDERER` and WASM
  `?renderer=auto|cpu|legacy` overrides.
- Show a compact typed badge such as `Vello · Auto`, `Vello · Cpu`, or
  `Legacy` on every renderer-backed card.

### px showcase

- Make every ordinary chart section construct the Vello-default builder.
- Keep the dedicated scatter diagnostic, but allow it to select CPU or Legacy
  for QA.
- Support native `PX_SHOWCASE_RENDERER` and WASM `?renderer=auto|cpu|legacy`.
- Give every capture a stable section/query key and renderer metadata. If the
  query override is intentionally limited to scatter diagnostics, document
  that scope; otherwise thread it through every ordinary section.

### UI-kit showcase and gallery

Finish and register the Audio Visuals section in `gpui-showcase` with spectrum,
vertical/horizontal meters, potentiometer, and volume knob examples. Add it to
the section enum, query routing, release manifest, and WASM gallery. Exercise
narrow widths, long labels, design-system spacing/typography tokens, and
keyboard/mouse focus states. The section must report `Vello · Auto` natively
and make CPU/Legacy fallback captures addressable for QA.

### Metadata and documentation

- Require non-empty `renderer`, `renderer_query`, capture id, viewport, and
  artifact path fields for renderer-backed manifest entries.
- Validate unique query keys and that generated URLs preserve the renderer
  override.
- Update crate READMEs, examples, gallery metadata, and `WHATSNEW.md` with the
  default, fallback rules, feature limitations, and Legacy escape hatch.
- Do not overwrite unrelated gallery/query changes in the dirty worktree.

## Automated test plan

### Contract and API tests

Add focused tests beside existing d3rs, px, and audio tests for:

- `Renderer2D::default()` and `VelloBackend::default()`;
- constructor defaults for every px chart builder and every audio visual;
- explicit `renderer_2d`, `vello_backend`, and compatibility
  `raster_backend` setter chaining;
- Vello CPU, Vello WGPU/Auto, Legacy, and feature-off compilation paths;
- typed unavailable-renderer errors (where applicable) and audio fallback;
- renderer metadata labels and query parsing (`auto`, `cpu`, `legacy`, invalid
  values, and missing values).

### Painter lifecycle tests

Use a fake window/device or test hooks to assert:

- forced CPU paints once and reuses the rasterizer/image;
- forced WGPU registers once and submits scenes without CPU image creation;
- successful `Auto` selects WGPU;
- unavailable or failing custom draw unregisters and selects CPU;
- unchanged `(scene_revision, width, height, scale)` does not recreate targets;
- revision changes submit a new scene but reuse size-dependent resources;
- resize/scale/device changes recreate only affected resources;
- old images are dropped before replacement;
- empty/zero-sized paints are safe; `Drop` unregisters exactly once.

### Deterministic CPU fixtures

Render fixed-size RGBA fixtures with fixed colors, bounds, scale factor, and
seeded data for:

- scatter, line, area, bars, and grouped bars;
- boxplot, pie/donut, and treemap;
- heatmap, contour bands, and isolines;
- spectrum and both meter orientations;
- potentiometer arc/ticks and volume-knob background/value/ring.

Compare with explicit antialias/color-space tolerances rather than exact
floating-point identity. Assert transparent backgrounds, clip bounds,
non-empty expected marks, stable output for empty/NaN input, and no writes
outside the element bounds. Store fixtures under the existing QA fixture tree,
with a small golden image plus a machine-readable scene summary where useful.

### Geometry and semantic parity

Feed identical validated data to Vello and Legacy and compare:

- normalized coordinates and scales;
- picking regions and hit results;
- legend/accessibility summaries;
- validation errors, empty data, NaN filtering;
- reversed/log axes, narrow layouts, resize, and high-DPI bounds.

Pixel identity is not required between rasterizers; semantic and scene-summary
parity is required.

### Lifetime and allocation tests

Warm spectrum, meter, potentiometer, and volume-knob updates, then assert:

- no repeated custom-draw registration or pipeline/rasterizer construction;
- no per-frame scene/image allocation beyond the documented update buffer;
- no image/resource growth after repeated resize cycles;
- smoothing state remains correct while repainting.

Use `gpui-profiler` or the existing allocation test helpers where available and
keep thresholds generous enough for platform allocator noise.

### Manifest and browser tests

Extend the existing Python manifest tests and screenshot scripts to check:

- every renderer-backed story has a non-empty renderer id and unique query key;
- generated gallery URLs include the renderer query;
- default, CPU, and Legacy captures are all addressable;
- wrong-size/missing-image artifacts, missing metadata, page errors, and
  console errors fail validation;
- WebGPU initialization can fall back to CPU instead of hanging or producing a
  blank capture;
- pixel differences stay within the documented tolerance.

Use the existing WASM gallery as the source of truth and re-record only affected
baselines. Keep browser paths free of blocking pollster/device polling and
synchronous readback.

## Verification matrix and order

Run the smallest relevant check after each workstream, then the full ladder:

1. `cargo fmt --all -- --check` and `git diff --check`.
2. d3rs Vello CPU/unit/integration tests, including the dedicated
   `vello2d_cpu_tests` fixture suite.
3. d3rs Legacy/no-default-features tests and a native WGPU/runtime-shader
   compile/test lane.
4. px library tests, no-default-features check, builder/API tests, and showcase
   binary check.
5. audio-kit default-Vello and no-default/Legacy tests, including allocation
   and audio visual fixtures.
6. `gpui-showcase` and `gpui-ui-kit` tests plus the Audio Visuals manifest
   tests.
7. Existing release/obvious checks: `just qa-gpui-obvious`.
8. Browser checks: `just wasm-check`, `just wasm-test`, `just wasm-visual`,
   and `just qa-visual`; run the gallery Python unit tests as part of the same
   lane.
9. On a host with the Metal toolchain, run the native WGPU/Metal visual lane
   and promote only clean, reviewed baselines. If Metal is unavailable, run
   the runtime-shader/CPU lanes, record the missing-toolchain limitation, and
   do not claim native Metal coverage.

The exact feature flags should follow each crate's `Cargo.toml`; every command
must be run once with Vello enabled and once with no default features where the
crate promises a Legacy build.

## Definition of done

- Every ordinary d3rs and px 2D mark, and every listed audio visual, defaults
  to Vello without producer-specific duplicate geometry.
- `Auto` has deterministic WGPU-to-CPU fallback; explicit CPU, WGPU, and Legacy
  choices remain observable and testable.
- Painter lifecycle counters prove resource reuse, correct unregister/drop, and
  safe resize/empty behavior.
- CPU fixtures cover all marks and audio primitives; semantic parity tests pass.
- d3rs, px, and UI-kit showcases visibly report renderer metadata and support
  stable default/CPU/Legacy QA selectors.
- WASM gallery manifests and screenshots validate renderer ids, query keys,
  artifact paths, browser errors, and documented pixel tolerances.
- Feature-off builds compile and retain the Legacy escape hatch.
- Documentation and release notes describe defaults, fallbacks, limitations,
  and how to reproduce each QA lane.
