## 1. Assessment

**The 2026-10-18 audit's core correctness and scene-retention programme was
implemented, fast, and it holds up at HEAD. The platform/power programme, the
compute-residency programme, and CUDA/MLX were not started.** Almost all
substantive audit work landed on 2026-10-18/19 (~40 commits, `1666e92d` …
`8a7c66c2`). Work after 2026-10-21 was the GPUI v1.25.2 bump (2026-10-24), the
performance baseline record (2026-10-31), and November product work
(spinorama, contour raster, tick/legend tuning) plus the fork-side
retained-frames port ("gpui-fast", 2026-11-07). No regression of an audited
fix was found in that later work; two new risks did arrive with it (§8, N1/N2).

Of the original findings:

- **Fully implemented:** C1 (clipping coordinates/precision), C2 (prepared-flow
  coherence). The implementation log's only two ticked boxes are justified.
- **Implemented except for one named sub-item:** C4 (5 of 6 bullets; sorted
  transparency remains an undocumented-on-GPU approximation), C5 (checked
  sizes on all default paths; no *total* device budget, VTU errors still
  `String`), Q1 (collector/comparator genuinely fixed and CI-wired; committed
  baseline is stale and local-only).
- **Substantially implemented, material remainder:** C3 (validity masks —
  everything except contours and all mesh IO), P1 (retained scene — everything
  except scalar-only updates and cross-chunk normals), P3 (pretext is now the
  model byte-budget cache; the d3rs mesh-image cache is untouched), P6
  (bounded read done; inbound aggregate queue bytes open).
- **Half done:** C6 (Windows + Web migrated to owned, generation-checked
  editor registries; AU, iOS, Linux and Android did not move), C7 (measurement
  identity fixed; grapheme editing untouched), P2 (host-GPU scene path exists
  but is behind an opt-in feature with **zero in-repo consumers**;
  transformation GPU flow is essentially as audited), P5 (shared volume
  storage only; acceleration structures and streaming export absent,
  `movie.rs` is byte-identical to the audited revision).
- **Not started:** P4 (table row ownership), §6 power/platform scheduling
  (including one confirmed Android liveness bug), §9 Phase C GPU
  classify/scan/compact + GPU volume, Phase D CUDA, Phase E MLX, real fuzzing,
  and every physical-device qualification item.
- **Overtaken by events:** §8 Taffy. The audit proposed an instrumentation
  pass and a retained-node *prototype* with a 20 % decision gate. Instead,
  retained views/Taffy nodes/text measurements shipped as the **default** in
  the GPUI fork (Nov "gpui-fast" port) with paired retained/scratch
  measurements but without the recorded decision gate or invalidation matrix.
  The audit's predicted cost — stale replay of views reading untracked
  state — already surfaced once (`34e67181`) and was fixed only in a test
  helper (N1).

Recommended order now (details in §9, "New steps"): close the remaining *correctness* holes
first (C3 contours/IO, C6 AU/iOS/Linux/Android ownership, Android animation
wake, C7 grapheme editing, `mux_mp4` deadlock), finish P1/P2 residency
(including actually enabling `gpui-gpu` in shipped configurations), then
P3/P4/P5 bounds, then re-run the §8 decision gate properly, then §6 power —
CUDA and MLX stay last and gated, exactly as the original audit sequenced
them.

## 4. Correctness findings — status detail

### C1 — FULL: GPU clipping coordinate spaces

Implemented as prescribed, beyond the audited regression list. Vertices are
rebased f64→f32 in `crates/gpui-scene3d/src/prepare.rs:187-189,274`;
`ClipPlane::relative_to(origin)` rescales the normal and computes a
compensated f64 offset (`crates/gpui-scene3d/src/scene.rs:69-89,246`); the
shader now tests `dot(local_position, plane.xyz) - plane.w`
(`crates/gpui-scene3d/src/shaders.rs:57,66,117`); camera matrices are
origin-relative (`crates/gpui-scene3d/src/camera.rs:251,284`).
`PlaneEquation::to_uniform` returns `SceneError::UnsupportedPrecision` for
zero/subnormal f32 coefficients and handles distant planes as a constant
half-space (`scene.rs:106-131`); the GPUI presentation falls back to the
software image on that error and recovers
(`crates/gpui-scene3d/src/gpu_element.rs:179-211`, test
`actual_presentation_decision_uses_and_retains_precision_fallback_image`
@ `crates/gpui-scene3d/src/element.rs:340`). Volume rays use
`ray_grid_relative_to(origin)` + local planes
(`crates/gpui-scene3d/src/volume.rs:262-268`); lighting is directional on
interpolated normals, hence translation-invariant.

Regression coverage matches the audit: origins 0, 1000.125, 1e9+0.125,
1e12+0.125 with exact GPU red-count = CPU
(`clipped_surface_is_translation_invariant` @
`crates/gpui-scene3d/src/gpu_render.rs:1945`); oblique multi-actor tests
with distinct origins (GPU/CPU coverage ≤4 px, byte-identical GPU across
translations) @ `gpu_render.rs:1992-2026`; CPU twin
`oblique_clipping_multiple_origins_and_fractional_translations_are_invariant`
@ `crates/gpui-scene3d/src/raster.rs:1291`; normal scales 1e-300/1e300 and
tangential origins 1e12/1e250. Commits: `13cb4dd0`, `10281d77`, `caf27a0c`.
Caveat: GPU coverage tests early-return without an adapter unless
`GPUI_REQUIRE_GPU=1` (this audit ran them in mandatory mode on Metal; they
pass). NVIDIA/browser qualification remains UNVERIFIABLE-HERE. On the
"picking" clause see correction §7.1.1.

### C2 — FULL: prepared-flow field coherence

`PreparedFlow::diagnostics(&mut self, Option<&[[f64;3]]>)`
(`crates/gpui-dataset-transformation/src/gpu.rs:915-918`) length-checks and
packs new velocities **before** `write_buffer`, then commits
`base.point_data[velocity_field].data` (`gpu.rs:919-933`), so the returned
dataset, later `diagnostics(None)` calls, and the GPU buffer share one
revision; an invalid update leaves buffer and base untouched.
`append_diagnostics` (`gpu.rs:127`) builds the result from that base.
Validity is preserved by construction: only `.data` is replaced;
`packed_velocities` zeroes masked storage with flag 0 and rejects unmasked
NaN/inf/unrepresentable f32 (`gpu.rs:94-120`); masked nodes stay missing
until a new problem is prepared (documented `gpu.rs:909-910` — the audit
asked to preserve validity, not to update masks, so this is not a missing
bullet).

Tests cover every audited regression: `prepared_flow_matches_cpu_and_updates`
@ `gpu.rs:1029` (zero update → Q = 0 **and** velocity = zeros,
`None`-after-update, CPU `q_criterion` recomputation on the returned field,
bad-length error, restore-to-rotation); atomicity/masking in
`metal_flow_kernels_preserve_missing_stencils_and_reject_invalid_updates_atomically`
@ `crates/gpui-dataset-transformation/tests/flow_validity.rs:267`. Commits:
`1666e92d`, `63350761`.

### C3 — PARTIAL: validity masks

A common contract now exists and most operations honor it.
`Field::is_valid` = exists + unmasked + all-finite, short masks fail closed
(`crates/gpui-mesh/src/field.rs:108-118`); `DataSet::validate` rejects
unmasked NaN/inf (`crates/gpui-mesh/src/dataset.rs:320,629`); one completion
path `validity::finish` produces masked NaNs without allocating a mask when
fully valid (`crates/gpui-dataset-transformation/src/validity.rs:14-68`).

FULL per operation, each with named tests: threshold All/Any for point and
cell fields (`threshold.rs:51-68`; `invalid_placeholders_never_match_either_threshold_mode`);
cell↔point conversion in exact/integer/plain mean paths (`convert.rs:49-109`;
`tests/validity_contracts.rs:64,112`, `tests/weighted_precision.rs:82`);
interpolation incl. zero-weight endpoint rule, no renormalising invalid
contributors away (`interp.rs:34-58`); CPU diagnostics requiring complete
stencils (`flow.rs:34,152`; `tests/flow_validity.rs:158`); GPU/Metal
diagnostics with exact mask equality vs CPU (`gpu.rs:99-111,640-644,1009`;
`tests/flow_validity.rs:267`); scene rendering (masked point scalar → NaN →
shader discard @ `prepare.rs:191-194`, `shaders.rs:111-114`; masked cell
owners excluded @ `prepare.rs:255-295`; `masked_point_and_cell_values_do_not_become_valid_colors`);
volume indexing (only all-valid tets @ `volume.rs:67` in scene3d);
warp/glyph (`warp.rs:33-120`, `glyph.rs:52-220`; `tests/geometry_validity.rs:17,97`);
streamlines/particles/LIC/tensor trace/FTLE via the shared strict stencil
(`streamline.rs:92`, `stencil.rs`; `tests/tracing_validity.rs:45,127`);
isosurface (`isosurface.rs:127` validate-first, `:158` all-valid tet rule);
calculators/expressions/statistics/histograms (`calculator.rs:35-127`,
`expression.rs:320`, `analysis.rs:82-132`); and beyond the audit list:
decimate, append, clip-sphere, probe, resample
(`tests/geometry_filter_validity.rs`, `tests/analysis_validity.rs`).
Geometry-only ops (smooth, transform, normals, feature edges, triangulate,
streamtube/ribbon line building) read no field values and carry masks by
clone — FULL by construction (minor unrelated nit: `smooth`/`transform`
validate input only, so a nonfinite λ/matrix can emit nonfinite positions).

**Remaining, concrete:**

1. **Contours ignore masks — the original C3 failure mode is still
   reproducible there.** `contour_lines` never reads `field.valid` and never
   calls `dataset.validate()` (`contours.rs:22-44`); `extract_cell` compares
   raw values to the level (`contours.rs:86-92`), so a finite masked
   placeholder crossing the level emits an isoline segment. Masked NaN is
   only accidentally safe (NaN comparisons are false). No masked test exists.
   Copy the `isosurface.rs:158` pattern.
2. **All mesh IO ignores masks.** `write_vtk`/`write_fields` dump raw values
   (`vtk_io.rs:45,86-110`): a masked finite placeholder is exported as a real
   measurement, masked NaN as literal `NaN`. The VTU/XDMF/surface writers and
   readers likewise have no `.valid` handling; readers build fields with
   `valid=None` then validate (`vtk_io.rs:205`, `vtu.rs:817`, `xdmf.rs:285`),
   so re-reading an exported masked-NaN field **fails validation**, and
   masked-finite values silently become valid on round-trip. No IO validity
   tests. (The implementation log keeps IO explicitly open — consistent.)
3. **Slice/clip:** geometry is position-only (defensible), interpolated
   point fields do honor masks via `interp` (`clip.rs:65-66`), cell fields
   are dropped (documented) — but there is no masked-input test at
   slice/clip level and no per-operation semantics statement in the docs,
   both of which the audit's Change text required.
4. **Time sampling:** behaviour verified (mask intersection +
   NaN-on-invalid rows @ `crates/gpui-mesh/src/time_series.rs:581-594,677`),
   but no masked test exists in that file, and the `data_shared` path keeps
   finite payload under an intersected mask — safe only through `is_valid`
   consumers. Test bullet downgraded to PARTIAL on adversarial re-check.

### C4 — PARTIAL (5 of 6 bullets FULL): backend semantics

- **Transfer alpha — FULL.** `Actor::is_transparent()` =
  `opacity<1 || active_transfer.map_or(color[3]<1, |tf| !tf.is_opaque())`
  (`scene.rs:415-420`); CPU blend pass never writes depth
  (`raster.rs:146,164-168,1071-1077`); GPU transparent pipeline has
  `depth_write=false` + alpha blending (`gpu_render.rs:505-510,674,1183`).
  Tests: `transfer_alpha_controls_the_render_pass` (α 0/0.25/1) @
  `scene.rs:456`, `transfer_alpha_blends_and_invalid_samples_leave_background`
  @ `raster.rs:1555`. Adversarial check of the flat-α + opaque-transfer hole:
  closed (`scene.rs:422-433`, test @ `:471-476`). Commit `1666e92d`.
- **Wireframe — FULL.** Preparation builds canonical deduped edges across
  chunk boundaries (`prepare.rs:151,218-230,494-516`); CPU `draw_wireframe`
  clips and alpha-blends them (`raster.rs:448-449,537-631`); GPU uploads a
  resident edge index buffer and draws a `LineList` wireframe pipeline
  (`gpu_render.rs:476-510,614-619,1196-1206`). Tests:
  `software_/gpu_wireframe_matches_edge_alpha_clipping_and_occlusion_contract`
  @ `crates/gpui-scene3d/tests/wireframe.rs:325,331`,
  `wireframe_buffers_stay_resident_across_camera_and_material_updates`,
  `wire_edges_are_unique_across_winding_and_chunk_boundaries`. Commit
  `171abbfc`.
- **Interpolation parity — FULL with documented caveat.** CPU
  `FragmentShader::color` does perspective-correct (1/w-weighted, f64)
  scalar+normal interpolation per fragment with a constant fast-path only
  when all vertex values are equal (`raster.rs:917-991`); clipping carries
  scalar+normal (`clipping.rs:66-76`); GPU uses hardware varyings
  (`shaders.rs:57-59`). The one remaining non-parity is explicitly
  documented: GPU quantised RGBA8 LUT vs CPU prepared transfer — byte-identical
  colours are not guaranteed (`raster.rs:69-72`, `shaders.rs:7-8`). Tests
  compare both backends to an independent ray reference
  (`tests/surface_interpolation.rs:254,278`). Commit `47299cd5`.
- **>6 clipping planes — FULL.** `MAX_CLIP_PLANES=6` (`shaders.rs:13`); GPU
  upload/material paths return
  `GpuRenderError::UnsupportedFeature("more than six clipping planes")`
  (`gpu_render.rs:557-561,862-865`); `packed_clip_planes` returns
  `SceneError::ResourceLimit` (`shaders.rs:292-296`); CPU iterates the full
  list uncapped (`clipping.rs:98`, `raster.rs:323,408`). A dedicated test
  exists: `uniform_builders_reject_excess_and_nonfinite_planes` @
  `shaders.rs:403-411` (this audit's first pass missed it; the adversarial
  pass found it). Latent footgun only: `scene_uniform_block_with_equations`
  (`shaders.rs:333`) silently truncates with `.min(MAX)` if ever called
  directly — no production caller does. Commit `1666e92d`.
- **Lines/points — FULL, with audit correction §7.1.2.** CPU lines are now
  truly clipped to the retained half-space (`segment_interval` +
  `interpolate_samples` @ `raster.rs:740-745`, `clip_line_vertices` @
  `clipping.rs:224-239`), points are drawn (`raster.rs:462-474`); GPU has
  LineList/PointList primitive pipelines per actor
  (`gpu_render.rs:692-740,1208-1212`). Tests:
  `software_/gpu_line_point_material_and_validity_contract` @
  `tests/primitives.rs:302,336`,
  `crossing_line_matches_explicitly_clipped_segment_at_large_origins`,
  `lines_crossing_user_planes_are_clipped_in_both_directions`. Commit
  `d4f651eb`.
- **Transparency ordering — PARTIAL (the only open C4 bullet).** No OIT/WBOIT
  was evaluated or implemented. CPU sorts transparent actors by bounds-centre
  and triangles by depth *within* each actor only (`raster.rs:170-180,434-435`);
  GPU sorts actors only (`gpu_render.rs:1144-1156`). The approximation is
  stated in the CPU `render()` doc (`raster.rs:72-73`) but **not** on the GPU
  path, and there is no intersecting-translucent-surfaces test (only
  non-intersecting `transparent_actor_blends_over_opaque`). Missing vs audit:
  WBOIT evaluation/decision, GPU-side statement, intersecting test.

### C5 — PARTIAL: checked sizes and budgets

- **Raster/volume frames — FULL on the default path.**
  `RenderLimits{max_dimension 16384, max_frame_bytes 64 MiB}` with u64
  `checked_mul` pixel counts capped at `usize::MAX` (wasm32-safe)
  (`crates/gpui-scene3d/src/limits.rs:15-101`); `raster::render()` defaults
  to it, 8 B/px covers colour+depth, the remainder bounds transparent-triangle
  scratch via `try_reserve_exact` (`raster.rs:81-261`); frame allocation
  failure is `SceneError::Allocation` (`limits.rs:104-113`); volume render
  uses the same limits (`volume.rs:221-256`). Structured errors:
  `SceneError::ResourceLimit{resource, requested, limit}` / `Allocation`
  (`lib.rs:84-99`). Tests:
  `dimensions_and_working_set_are_checked_before_allocation`,
  `transparent_scratch_limits_cover_growth_peak_and_leave_opaque_work_available`.
  Adversarially confirmed on the ordinary path (`render()` delegates to the
  default limits; `SceneElement` paint pre-checks with the same default @
  `element.rs:65`) — not opt-in only. Commits `1666e92d`, `4d85b18b`.
- **GPU target/readback/upload — PARTIAL.** `create_target` defaults to
  `RenderLimits` and clamps to `max_texture_dimension_2d`
  (`gpu_render.rs:960-978`); readback layout checks padded rows and aggregate
  working bytes and `read_rgba` checks `max_buffer_size`
  (`gpu_render.rs:1226-1370`); `upload_plan` device-checks every buffer and
  sums all chunks + primitives + per-actor material + the previous scene
  against `GpuUploadLimits.max_resource_bytes` (256 MiB default, wired into
  the default upload path @ `gpu_render.rs:542-571`, not opt-in only);
  primitive CPU staging capped per chunk (4 MiB). **Missing:** the aggregate
  explicitly excludes pipelines, targets, CPU prepared data and driver
  overhead and is documented as "not a physical VRAM or total device-memory
  limit" (`limits.rs:33-40`) — the audit's host-supplied *total* byte budget
  does not exist; per-frame uniform staging is checked only against
  `max_buffer_size`. Tests: upload-plan boundary tests @
  `gpu_render.rs:1461-1572`, 65536×65536 readback rejection,
  `tests/gpu_upload_limits.rs:11`. Commit `4d85b18b`.
- **VTU decompression — PARTIAL (bounds FULL, errors not).**
  `VtuReadLimits{input 64 MiB, array 32 MiB, decoded 128 MiB, arrays 4096,
  blocks 65536}` (`crates/gpui-dataset-transformation/src/vtu.rs:52-76`) is

  `ContourGenerator` (`:56,66-69` vs `:75`), so a cache hit still allocates
  and builds an unused generator every render. Move the hit check first; no
  test exists. (Commit `0ca6371c`.)
- **N5 — process note: the November "perf-cache" commit adds no chart cache
  in this repo.** `784dd106` is a 0.11 version bump + fork retention + a
  small accessibility guard + the `retained_frames` bench; `34e67181` is a
